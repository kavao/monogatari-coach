## 目的

First Reader Mode と Interest Check Mode で、評価結果の所在を曖昧にしない。

横断正本は **`.rulesync/rules/workflow-specification.md`** の「評価出力の保存先」。このスキルは、その保存条件を満たすための実行手順を定める。

## 保存先（必須）

| 種別 | 参照する技法 | 保存先 |
|------|--------------|--------|
| First Reader / 下読み・書評 | `_how_to/reader.md` | `novels/<作品>/_reader/YYYYMMDD_HHMM.md` |
| Interest Check / 一般読者の興味判定 | `_how_to/standard_reader.md` | `novels/<作品>/_reader/interest_YYYYMMDD.md` |

- `YYYYMMDD_HHMM` は実行時刻を使う。
- `_reader/` が無ければ作成する。
- チャット欄に本文を書いただけでは完了ではない。評価本文は必ず上記ファイルへ保存する。
- **ゲート段階（G1/G2/G3）によってファイル名は変えない**。同じ章を異なる段階で評価した場合も、実行時刻で区別する。

## 評価前チェックリスト

評価を開始する前に次の順序で確認する。

1. `config.md` を Read し、作品名・ジャンル・ターゲット層・novel_ID を確認する。
2. 対象 `_novel_text/*.md` を Read する（G1: 先頭〜3,000字相当、G2: 対象章の1ファイル、G3: 全ファイル）。
3. `python tools/novel_char_count.py novels/<作品>` を実行し、対象範囲の文字数を取得する。
4. 前回の `_reader/*.md` があればパスと総合点を確認し、保存ファイルの冒頭に「前回書評: パス・総合点」として引用する。

## First Reader の内容

`_how_to/reader.md` に従い、最低限次の項目を保存する。

### 必須保存項目

| 項目 | 内容 |
|------|------|
| 日付・時刻 | ファイル名と一致した実行時刻 |
| 対象範囲 | 作品ID・章・文字数（`novel_char_count.py` 実行値） |
| ゲート段階 | G1冒頭 / G2章完 / G3全文 |
| 判定 | 「読むべき」または「読まなくていい」（中間表現は使わない） |
| 総合点 | XX / 100 |
| 5段階評価 | XX.X / 5.0 |
| 評価内訳 | 冒頭の牽引力/キャラクター/プロット期待値/文章力/わかりやすさ/独創性 |
| 判定理由 | 簡潔に |
| 得られる読後感の期待値 | 最後まで読んだ場合の満足感・余韻の予測 |
| ジャンル特化評価 | 該当なしの場合は「なし」 |
| 足切り理由 | 「読むべき」→続きを読む価値の核を明示 / 「読まなくていい」→決定的に弱かった要素を明示 |
| 改善点 | 各観点について次に何を直せば評価が上がるかを具体的に |

### 足切り判定基準

- **70点以上**: 原則「読むべき」
- **55〜69点**: 強い美点が1つ以上あれば「読むべき」— **美点の内容を「足切り理由」節に必ず明記する**
- **54点以下**: 原則「読まなくていい」

配点と閾値の定義は `_how_to/reader.md` を正とする。

### 5段階換算

`5段階 = round(総合点 / 20, 1)` を目安とする。LLM が定性調整して併記してもよいが、**足切り判定は100点閾値を優先**する。

## Interest Check の内容

`_how_to/standard_reader.md` に従い、最低限次を保存する。

- ペルソナ設定
- タイトル、冒頭3行、最初の1ページの第一印象
- 判定（継続読了／読み飛ばし／ブラウザバック等）
- 興味のフック、または離脱の決定打

## 足切り実施後の `_meta.md` 更新

First Reader（足切り）実施後は、作品 `_meta.md` の **「IV. 評価・足切り履歴」** 節を更新する（テンプレートは `_how_to.example/meta.md` を正とする）。

更新する項目:
- **足切りステータス**: 直近ゲート段階の判定に応じて更新する（未 / G1合格 / G2合格 / G3合格 / 不合格）
- **最新 First Reader**: 日時・ゲート段階・総合点・判定・保存ファイルパス
- **評価履歴表**: 新しい行を追記する（既存行は削除しない）

複数回評価した場合の記録形式（例）:

```markdown
## 2. 最新 First Reader（足切り）
- **日時**: 20260608_1300
- **ゲート段階**: G2
- **総合点**: 75 / 100
- **判定**: 読むべき
- **ファイルパス**: `novels/073_寝息に溶けるボディー/_reader/20260608_1300.md`

## 4. 評価履歴（改訂前後の推移）
| 日時 | ゲート | 総合点 | 判定 | ファイル |
|------|--------|--------|------|---------|
| 20260608_1200 | G1 | 74 / 100 | 読むべき | `_reader/20260608_1200.md` |
| 20260608_1300 | G2 | 75 / 100 | 読むべき | `_reader/20260608_1300.md` |
```

**更新タイミング**: 評価ファイルを `_reader/` に保存した直後。チャットへの完了報告前に行う。

## 長文 G3 の分割評価（S-3-3）

G3（全文）評価で全文一括読み込みが困難な場合（目安: **合計30,000字超**、または章単体で **8,000字超**）、章ごとに部分点を集計して加重平均する。

**重要**: 合計30,000字超の作品で G3 を実施する場合、Synopsis（`_reader/synopsis_YYYYMMDD.md`）を先行して作成することは**必須**である（P2-4）。Synopsis なしに G3 の長文評価を開始しない。Synopsis の作成手順はスキル **`novel-evaluation-output`** の「Step A」を参照する。

### 手順

1. Synopsis を先行して `_reader/synopsis_YYYYMMDD.md` に保存する（**必須**: 合計30,000字超の場合）。
2. `novel_char_count.py` で全章の文字数を取得する。
3. 章グループごと（`novel_text01_*` を「第1章」等）に G2 相当の採点を行う。
   - 作業ファイル `_reader/_work/<YYYYMMDD>/ch01_eval.md`〜`chNN_eval.md` に保存する（長文パイプライン）。
   - 短編（30,000字未満）では章別作業ファイルを省略し、`_reader/YYYYMMDD_HHMM.md` に直接まとめてよい。
4. `aggregate.md` で加重平均を記録する:

```
最終総合点 = Σ（章スコア × 章文字数） ÷ 合計文字数
```

5. 最終スコアを `_reader/YYYYMMDD_HHMM.md`（G3 足切り）または `score_YYYYMMDD_HHMM.md`（Editor Score）に保存し、aggregate.md への参照リンクを記載する。

### 注意事項

- 加重平均はあくまで補助指標。各章に明確な弱点がある場合は総合点よりも「章ごとの足切り理由」を優先して判断する。
- G3 全体の閾値（70 / 55–69 / 54）は加重平均後のスコアに適用する。
- 長文パイプラインの完全な手順は **`novel-evaluation-output`** スキルを参照する（Editor Score との統合手順はそちらを正とする）。

## チャットで返すもの

チャットには、保存した評価本文の要約だけを返す。

- 判定
- 重要な理由を1〜3行
- 改善ポイントの要約
- 保存先ファイルパス

## 査証ログとの関係

- `_reader/` は評価本文の正本。
- `_workingspace/log/` は「評価を実施し、どのファイルへ保存したか」という作業事実だけを追記する。
- 査証ログの追記はスキル **`workspace-audit-log`** と `tools/workspace_audit_log.py append` に従う。
