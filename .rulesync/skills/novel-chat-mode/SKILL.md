## 目的

チャットモードは、企画から本文までを「セッション単位のゲート」で進める対話型執筆方式である。ユーザーとの方向合わせを小さく繰り返しながら作品を育て、必要に応じて TRPG セッション形式のプレイログを小説に変換する。

正本はすべて `novels/<作品>/` 配下に置く。チャットモードで変わるのは「進め方」だけであり、ファイルの所在と完了扱い条件は既存ルールと同一とする。

## 使う場面

- ユーザーが「チャットモードで新規作品を始めたい」と指示した。
- 「TRPG セッション形式で物語を進めたい」と指示した。
- 方向を見ながら少しずつ書きたい、連載で毎回ゲートを踏みたい。
- 設定は必要なところだけ厚くしたい。

## 選択肢提示ルール

チャットモードでは、物語や攻略の意思決定ポイントで行動選択肢を提示することを基本とする。ユーザーが自由記述で返してもよいが、通常は番号や短いラベルで選べる形にして、迷いを小さくする。

**選択肢を必ず出すタイミング:**

- 物語の変化点: 出会い、別れ、対立、秘密の開示、場所移動、章・シーンの節目など、選択によって次の展開や人物関係が変わる場面。
- 攻略・ゲーム性のある場面: リスク、リソース、時間制限、探索順、戦闘、交渉、好感度、フラグ、手がかり、パラメータ更新などが関わる場面。
- 合意ゲート: 作品契約、あらすじ、シーンカード、セグメント完了後の OK / 修正 / 方針変更など、制作上の判断が必要な場面。
- ユーザーが「選択肢を出して」「どう動ける？」などと求めた場面。

**選択肢を省略・縮小してよいタイミング:**

- 直前の選択結果を受けた描写継続で、まだ実質的な分岐が発生していない場面。
- 情報整理、要約、保存報告、文字数報告など、ユーザーの判断を急がない場面。
- ユーザーが自由記述で進めたい意図を示している場面。

省略する場合も、次の判断点が近いなら「次の分岐で選択肢を出します」のように案内してよい。

**必須形式:**

- 行動選択肢を最低2つ出す。
- 行動選択肢とは別に、システム操作・確認・保存・中断・Other などの非物語的な選択肢を最低1つ出す。
- 選択肢は、現在の Phase と直前の会話に即して具体化する。
- 選択肢には必要に応じて、物語への影響や攻略上の含みを短く添える（例: 「関係値が動きやすい」「危険だが手がかりが増える」）。
- TRPG セッション中は、物語内の行動を2つ以上提示し、必要に応じて「自由行動」「状態確認」「セッション終了」などを併記する。
- 作品契約・あらすじ・シーンカードなどの合意ゲートでは、「採用」「調整」「別案」など、編集判断として選べる形にする。

**表示例:**

```text
次の行動を選べます。
1. 左の扉を開けて、音の正体を確かめる
2. 机の下に隠れて、誰が来るか待つ
3. 状態確認: 現在のパラメータを見る
4. Other: 別の行動を自由に指定する
```

選択肢はユーザーを縛るものではなく、対話の足場である。ユーザーが選択肢外の指示を出した場合は、それを優先して自然に続ける。

## design_specification.md への同期

チャットモードでは、会話やセッションの内容を適宜 `design_specification.md` に同期し、後から作品全体の流れを掴めるようにする。逐語ログは `_chat/sessions/` に残し、`design_specification.md` には設計・流れ・分岐結果の要約だけを反映する。

**同期するタイミング:**

- Phase 1 のあらすじを確定・更新したとき。
- Phase 3 のシーンカードに同意したとき。
- Phase 4 のセグメント執筆が完了し、本文へ反映したとき。
- TRPG セッションで、物語分岐・攻略フラグ・パラメータ・人物関係が大きく動いたとき。
- 方針変更により、既存の章構成・伏線・結末方向が変わったとき。

**反映する内容:**

- 章・シーンの流れ: 何が起き、誰が何を選び、状況がどう変わったか。
- 選択結果: 採用された選択肢、発生した代償、得た手がかり、未選択ルートの扱い。
- 攻略要素: フラグ、好感度、関係値、リソース、危険度、手がかり、未解決課題。
- 次回の見通し: 次シーン候補、回収したい伏線、注意すべき矛盾。

**書き方:**

- `design_specification.md` に既存の章構成がある場合は、該当章・該当シーンへ短く追記する。
- 既存構成が薄い場合は、「チャットモード進行ログ」「現在の章・シーン進行」「攻略・分岐メモ」などの節を作り、箇条書きで更新する。
- 逐語的な会話、長い GM 文、`[STATE UPDATE]` の全文は入れない。必要な数値・フラグだけを要約する。
- 同期後は `_meta.md` の次回タスクとも矛盾しないか確認する。

## Phase 0〜4 の手順

### Phase 0: 導入（作品契約）

以下の6項目をチャットで確認し、`proposal.md` または `_meta.md` の「作品契約」節に書き込む。

1. 読後感（読者が何を感じるか）
2. 主軸（誰の・何の物語か）
3. トーン（重さ・ユーモア・文体の温度）
4. 尺感（短編／連載／長編）
5. 結末の方向（ハッピー／ビター／オープン等）
6. 禁止・必須（やらないこと・必ず入れたい要素）

**完了条件**: 6項目がファイルに存在し、ユーザーが「この方向で」と明示したこと。

---

### Phase 1: あらすじ

- 作品契約6項目との整合を一言チェックしてから書く。
- 全章の詳細プロットは書かない（10〜20行のビート列程度）。
- 矛盾があれば契約かあらすじのどちらを直すかユーザーに確認する。

**反映先**: `proposal.md` のあらすじ。必要になった時点で `design_specification.md` へ昇格。

**完了条件**: `proposal.md` にあらすじが保存され、契約との整合確認メモが残っていること。必要に応じて `design_specification.md` にも章・シーンの流れを同期する。

---

### Phase 2: 執筆前パック（ライト版）

`character.md` ライト版と `world.md` アンカー版を揃える。最初から百科全書にしない。

**`character.md` ライト版の最低限:**
- 名前・年齢・役割・一人称・口調
- 外見の要点（後の Tag Mode 用に最低限）
- 目的・欠点・他者との関係（各1〜2行）
- 成長弧1行（任意だが推奨）

**`world.md` アンカー版の最低限:**
- 舞台の時代・場所
- 物語に効くルール3つ（魔法・社会・技術など）
- 物語開始時点の状況

**TRPGモードを使う場合は、この Phase で `_chat/rulebook.md` も作成する**（後述）。

**完了条件**: `tools/novel_project_check.py novels/<作品>` が通り、ユーザーが「執筆開始OK」と明示したこと。

---

### Phase 3: シーンカード

今回書く1シーンだけを具体化する。全章一括はしない。

シーンカードの内容:
- 場所・時間・登場人物
- 開始状態 → 変化 → 終了状態
- このシーンで読者に伝えたいこと1つ
- 次シーンへのフック（任意）

**反映先**: `_meta.md` の「今シーン」節と `design_specification.md` の該当章・該当シーン。たたき台は `_chat/scene_cards/` に置いてよい（副本）。

**完了条件**: ユーザーがシーンカードに同意したこと。

---

### Phase 4: セグメント執筆

**セグメントの単位**（優先順）: シーン1個 → 項ファイル1本 → 目標字数（約4000字）

**1セグメントの手順**:
1. シーンカードと `_meta.md` を読む
2. `_novel_text/` に執筆・追記する
3. `tools/novel_char_count.py` または `Read` で確認する
4. `_meta.md` を更新（進捗・伏線・次シーン）
5. `design_specification.md` に、セグメントで起きた出来事・選択結果・攻略要素を要約同期する
6. チャットには **要約・更新パス・文字数・設計同期の有無** のみ返す

**ゲート（ユーザー判断）**:

| 判定 | 次のアクション |
|------|----------------|
| OK | 次のシーンカードへ（Phase 3） |
| 修正 | 同一セグメントを清書（`novel-refinement-output` 準拠） |
| 方針変更 | Phase 1 または Phase 0 へ戻る |

**完了条件**: 正本 `_novel_text/*.md` に書き込み済み・確認済み・パス明示済み（`concepts.md` の「完了扱い条件」に準拠）。

## TRPGモード: rulebook.md の自動生成

Phase 2 の終わりに、作品情報から `_chat/rulebook.md` を自動生成する。

### 生成手順

1. `proposal.md` のジャンル・トーン・読後感を読む
2. `world.md` の世界ルール（魔法・技術・社会）を確認する
3. `character.md` の主要人物数・関係構造を確認する
4. 下記ジャンル別プリセットから最近傍を選ぶ
5. 作品固有の要素を加え、不要なパラメータを削る（合計8〜12個を目安）
6. 各パラメータに「名前・尺度・初期値・更新条件・`[STATE UPDATE]` での表記例」を書く
7. `_chat/rulebook.md` に出力し、ユーザーに確認を求める

生成後、ユーザーが承認するまで `state/char_state.md` の作成に進まない。

### パラメータ4分類と尺度

どんな作品・ジャンルでも、パラメータはおおよそ4カテゴリに収まる。

| カテゴリ | 代表例 | 典型的な尺度 |
|---------|--------|------------|
| **個人能力** | 体力・精神・知性・魅力 | 0〜10 数値 / A〜E ランク |
| **成長・段階** | 成長段階・覚醒度・習得スキル | 段階型（未覚醒/覚醒/変容）|
| **関係性** | 好感度・信頼度・誤解度・恐怖 | 0〜10 数値（正負あり可）|
| **物語状態** | 緊張度・進行度・勢力バランス | カテゴリ型 or 0〜100% |

**尺度の選び方**:

| 尺度 | 向いている用途 | 更新の粒度 |
|-----|-------------|----------|
| 0〜10 数値 | 好感度・能力値など連続変化するもの | ±1〜3 |
| 0〜100% | 進行度・目標達成度など割合で見たいもの | +5〜20% |
| 段階型（3〜5段） | 成長・状態など離散的に変わるもの | 1段ずつ昇降 |
| カテゴリ型 | 緊張度（低/中/高/臨界）など質感で表すもの | 1段ずつ昇降 |
| フラグ（ON/OFF） | 秘密の露出・イベント発生など一方向のもの | ON 後は戻らない |

**原則**: カテゴリあたり2〜3個に絞る。「物語に効いているか」で削る。

### ジャンル別プリセット

| ジャンル | 個人能力 | 成長・段階 | 関係性 | 物語状態 |
|---------|---------|-----------|--------|---------|
| **ファンタジー冒険** | 体力・魔力・技量 | 熟練段階（3段） | 仲間信頼度 | クエスト進行度・緊張度 |
| **恋愛・青春** | — | 自己肯定感段階 | 好感度・親密度・誤解度 | 関係の段階・緊張度 |
| **政治・宮廷** | 知性・弁舌・胆力 | — | 勢力信頼度・警戒度 | 勢力バランス・秘密の共有度 |
| **ホラー・ミステリー** | 精神力 | — | 協力度 | 精神安定度・手がかり収集度・危険度 |
| **成長物語（師弟）** | 基礎能力・集中力 | 成長段階・スキル習得フラグ | 師弟信頼度 | 試練進行度 |
| **汎用（ジャンル不明）** | 体力・精神 | 成長段階（3段） | 主要関係値 | 緊張度・章進行度 |

テンプレートは `_how_to.example/trpg_rulebook.md` を参照する。

## TRPGセッションの進め方

### セッション開始時にロードするもの

1. `_chat/rulebook.md`（パラメータ定義・世界ルール）
2. `_chat/state/world_state.md`（世界の現在値）
3. `_chat/state/char_state.md`（キャラクターの現在値）
4. 前回の `_chat/sessions/chat_XX_YY.md`（直前のログ）

### STATE UPDATE プロトコル

GM（LLM）の地の文のあとに `[STATE UPDATE]` ブロックを挿入し、ログに差分を残す。

```
---GM---
霧の中で二人が向き合った。リオンの声が、はじめて揺れた。

[STATE UPDATE]
リオン ← アイラ 関係値: 友好 6 → 8
緊張度: 中 → 高
第1章進行: 60% → 75%
```

- パラメータ変化は「旧値 → 新値」の形で書く。
- 変化がないターンは `[STATE UPDATE]` ブロックを省略してよい。
- セッション終了時に `_chat/state/*.md` へ現在値を書き戻す。

### 2つの小説化パス

| パス | いつ使う | 手順 |
|-----|---------|------|
| **GM文体がそのまま小説** | セッション中から文学的に書いている場合 | `sessions/` のログを `_novel_text/` にコピー → `[STATE UPDATE]` ブロックを除去 |
| **ログ → 清書** | 対話的に進めて後で文体を整える場合 | ログを素材にLLMが清書して `_novel_text/` に書き出す |

どちらのパスでも `_novel_text/` への書き込み・確認・パス明示が完了してから「完了」とする。

### ファイル構造とリセット後の永続性

```
novels/XXX/
  _chat/
    rulebook.md          ← パラメータ定義・世界ルール（副本）
    state/
      world_state.md     ← 世界状態の現在値（副本）
      char_state.md      ← キャラクター現在値（副本）
    sessions/
      chat_01_01.md      ← 第1章セッション1のプレイログ（副本）
      chat_01_02.md
  _novel_text/
    novel_text01.md      ← 小説化された成果物（正本）
```

`_chat/` はすべて副本。完了扱いは `_novel_text/` への反映後とする（`concepts.md` の「正本と副本」に準拠）。
