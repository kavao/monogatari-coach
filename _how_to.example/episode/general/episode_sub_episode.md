# 子エピソードによる増量

一般エピソード技法のうち、本筋を壊さず、意味の密度を落とさずに文章量を増やすため、親エピソードの内部へ子エピソードを挿入する技法。索引は [episode_.md](episode_.md)。
（関連文書：[文章の伸縮操作規定](../../length_ops.md)／[足を引っ張るキャラクターの設計](episode_hindrance.md)／[エピソード構造](episode_structure.md)／[序盤／中盤／終盤／多人数テンポ](episode_tempo_ensemble.md)）

**発動条件**: 加筆工程で出来事を足して分量を増やすとき（規定量調整から加筆工程へエスカレーションし、ユーザーが承認した場合を含む）。清書と規定量調整では使わない。子エピソードの追加は物語上の出来事（CANON）を増やす操作であり、[文章の伸縮操作規定](../../length_ops.md) の OP-E に当たる。

---

## 1. 定義

**子エピソード** とは、親エピソードの目的・因果・感情を補強する、小さな目的を持った出来事をいう。

子エピソードによる増量は、物語を横に膨らませることではなく、**親エピソード内部の因果を細かくすること** を指す。

```text
A → B
```

を

```text
A → a1 → a2 → a3 → B
```

にする。

### 適用範囲

対象は **親エピソードの内部** に限る。章の冒頭・締めくくり・章間の繋ぎなど、どの親エピソードにも属さない余白は対象外とし、「緩急調整」として扱う（`BREATHE` 相当の場面を置く場合も、§5 の接続義務は課さない）。

ただし、その余白が後続の親エピソードの前提を担う場合は、その親エピソードの子として扱い、本技法を適用する。

---

## 2. 挿入前の手順：親エピソードの分解

子エピソードを追加する前に、親エピソードを次の 4 要素に分解する。

| 要素 | 内容 |
|---|---|
| 目的 | 誰が何をしようとしているか |
| 障害 | 何がそれを阻むか |
| 結果 | 成功・失敗・別の何か |
| 変化 | 前後で人物・関係・状況の何が変わったか |

子エピソードは、上記のうち **薄い・唐突な箇所にだけ** 挿入する。どの要素も十分である場合、その親エピソードは増量の対象にしない。

---

## 3. 子エピソード生成演算子

| 演算子 | 呼称 | 型 | 増やすもの | 適用場面 |
|---|---|---|---|---|
| `INTERRUPT` | 障害挿入 | 障害・分割 | 行動量 | 障害が軽い／山場が一発で終わる |
| `PREPARE` | 準備挿入 | 準備・前提補強 | 手順・計画・伏線 | 結果が唐突 |
| `DISCOVER` | 情報挿入 | 情報 | 理解・世界説明 | 状況の意味が伝わらない |
| `RELATE` | 関係挿入 | 関係 | 人間関係 | 協力・対立の根拠が弱い |
| `HESITATE` | 逡巡挿入 | 感情 | 心理変化 | 決断が軽く見える |
| `CONSEQUENCE` | 余波挿入 | 結果・反響 | 余波 | 出来事の重みが伝わらない |
| `MIRROR` | 対照挿入 | 対比・並行視点 | テーマの多面性 | 主題が一面的 |
| `BREATHE` | 余白挿入 | 日常・余白 | 緩急・関係性 | 緊張が続きすぎて平板 |

### 配置指針

同一の親エピソードに複数の演算子を適用する場合は、緊張曲線上の位置で使い分ける。

| 位置 | 向く演算子 | 理由 |
|---|---|---|
| 親の冒頭〜序盤 | `PREPARE` / `DISCOVER` / `RELATE` | 目的と前提を固める |
| 山場の直前 | `INTERRUPT` / `HESITATE` | 緊張を引き上げ、決断を重くする |
| 山場の直後 | `CONSEQUENCE` | 結果の重みを定着させる |
| 緊張の谷 | `BREATHE` | 緩急をつける（連続使用は §7 平坦化に該当） |
| 位置を問わない | `MIRROR` | ただし山場の直前直後は視点が散るため避ける |

相性の目安：

- `DISCOVER` → `HESITATE`：得た情報が迷いを生む流れは自然に連鎖する
- `INTERRUPT` → `CONSEQUENCE`：障害の結果が後に響く形にすると §5 を満たしやすい
- `BREATHE` → `INTERRUPT`：緩めた直後に障害を置くと落差が出る
- 同一演算子の連続は原則避ける（§7 コピー型・平坦化の予防）

### 複数子エピソードの推奨順序

```text
① 前提を作る    PREPARE / DISCOVER / RELATE
② 緩める        BREATHE（必要な場合のみ）
③ 圧をかける    INTERRUPT / HESITATE
—— 親の山場 ——
④ 響かせる      CONSEQUENCE
```

`MIRROR` は ① か ④ に置く。この順序は因果を「原因 → 緊張 → 結果」の向きに揃えるための原則であり、意図的な倒置（結果を先に見せて原因を後から明かす等）を行う場合は記録（§11）の `order_note` に理由を残す。

例：親エピソード「A が B に告白する」に子を 3 つ入れる場合

```text
DISCOVER     B に好きな人がいるらしいと聞く
 ↓
HESITATE     告白直前に怖くなる
 ↓
（告白）
 ↓
CONSEQUENCE  B の態度が微妙に変わる
```

### 適用例：親エピソード「A が B に告白する」

| 演算子 | 子エピソード |
|---|---|
| `INTERRUPT` | 告白しようとするが、友人が割り込んでくる |
| `PREPARE` | 何を言うか友人に相談する |
| `DISCOVER` | B には好きな人がいるらしいという噂を聞く |
| `RELATE` | B と帰り道で二人きりになり、距離が縮まる |
| `HESITATE` | 告白直前になって怖くなる |
| `CONSEQUENCE` | 告白後、B の態度が微妙に変わる |
| `MIRROR` | 友人 C が別の相手への告白に失敗する様子を見る |
| `BREATHE` | 放課後、いつもの店で B と何気ない会話をする |

## 4. 子エピソードの内部構造

子エピソード自身にも、最低限次の構造を持たせる。

```text
目的 → 障害 → 判断 → 結果
```

大事件である必要はない。増量の用途では「行って帰ってくる」程度の小ささが適切である。

```text
小さな目的 → 小さな問題 → 小さな判断 → 本筋へ復帰
```

### 悪い例（描写の水増し）

> 主人公は市場を歩いた。店がたくさんあった。果物を見た。パンも売っていた。人が多かった。

### 良い例

> 主人公は旅の食料を買おうと市場へ寄った。ところが保存食は戦争の影響で値上がりしていた。所持金では足りない。仕方なく安い干し肉だけを買った。

- 目的：食料を買う
- 障害：値上がり
- 判断：妥協
- 結果：食料不足（→ 後に「山中で食料が尽きる」へ接続）

### 連鎖例：親エピソード「王都へ行く」

```text
王都へ行く
 ↓
馬車が故障する              （INTERRUPT）
 ↓
近くの村で修理を待つ
 ↓
村人から王都の疫病を聞く    （DISCOVER）
 ↓
馬車が直り、王都へ向かう
```

## 5. 必須規則：親への接続

文章量を増やす目的で子エピソードを追加する場合、その子エピソードは親エピソードとの間に **少なくとも 1 つの接続** を持たなければならない。また、状態変化（[文章の伸縮操作規定](../../length_ops.md) の `state_change`）を最低 1 件持たなければならない。

接続とは以下のいずれかをいう。

- 原因を追加する
- 障害を追加する
- 情報を追加する
- 人間関係を変化させる
- 感情を変化させる
- 後続イベントの条件を作る
- 親イベントの結果を拡張する

本筋に何も返さない子エピソードは禁止する。

### 複数接続の扱い

1 つの子エピソードが複数の接続を同時に満たすことを推奨する。接続数が多いほど削除テスト（§10）に強くなり、同じ字数でも意味の密度が上がる。

### 持ち帰りのある子と、局所的効果だけの子

子エピソードが本筋へ返すものは二種類ある。

| 種類 | 内容 | 例 |
|---|---|---|
| 持ち帰り（`carry_back`） | 後の場面で参照・使用されるもの | 疫病の噂を聞く → 後で王都の封鎖に驚かない |
| 局所的効果（`local_payoff`） | 後では使われないが、その場面自体が読者に与えるもの | 人物への愛着・情緒・笑い・世界の手触り・緊張後の休息 |

局所的効果だけを持つ子エピソードは、次の条件をすべて満たせば許容する。

- 状態変化を最低 1 件持つ
- 接続として「感情を変化させる」または「人間関係を変化させる」を満たし、その変化が子エピソードの中か直後の親場面の行動・台詞に表れる
- 局所的効果を具体的に書ける（「雰囲気を出す」「世界観を伝える」のような抽象的な記述は空とみなす）

### 弱い接続の判定

接続の種類を満たしていても、次のいずれかに該当する場合は **弱い接続** とみなす。

- 持ち帰りのある子で、追加した情報・関係・感情が、以降の本文で一度も参照・反映されない
- 追加した障害が、判断も結果も生まずに解消される
- 感情の変化が、行動や台詞に表れない

弱い接続しか持たない子エピソードは、次のいずれかで補強する。

1. 後続場面で一度参照させる（最小の補強）
2. もう 1 種類の接続を足す（例：情報追加 ＋ 感情変化）
3. 局所的効果の条件（上記）を満たすように書き直す
4. 補強できない場合は削除し、別の演算子で作り直す

## 6. 優先規則：前倒し

新規要素を追加するよりも、**後続で必要になる人物・物・情報を前倒しして子エピソード化する** ことを優先する。

例：後半で「主人公が医者に助けられる」予定 → 前半で「村で医者と知り合う」子エピソードを置く。

前倒しは、増量と同時に伏線・人物導入・世界説明を兼ねる。

## 7. 禁止パターン

| 名称 | 内容 | 例 |
|---|---|---|
| コピー型 | 本質的に同じ障害・同じ結果の事件を繰り返す（表面上の相手や場所が違っても、障害の性質と結果が同じなら該当） | ゴブリンと戦う ×3／相手がオークに変わっても「戦って勝つ」だけなら同じ |
| リセット型 | 終了時に完全に元へ戻る | 財布を落とす → 見つかる → 何も変わらない |
| 無関係型 | 人物・世界・因果・感情のどれにも接続しない | 魔王討伐の途中で無関係な釣り大会 |
| 重複型 | 本筋や他の子と同じ情報・感情を運ぶ | 既出の設定を別人物が再説明する |
| 主従逆転 | 子が親より印象に残り、軸を食う | 寄り道の脇役が主役化する |
| 平坦化 | `BREATHE` の連続で緊張曲線が平らになる | 日常場面が 3 つ続く |

リセット型の改善例：

```text
財布を落とす → 探す → 少女が拾っている → 少女と知り合う
```

## 8. 構造制約

- 入れ子は **2 階層まで** とする。

```text
MAIN
└ EPISODE
   └ SUB-EPISODE
```

- 1 つの子エピソードを長くするより、短い子エピソードを複数配置する。
- 子エピソードの総量が本筋の推進力を上回らない比率に保つ。

## 9. 不足量に応じた手段の選択

目標字数に対する不足率により、増量の手段を切り替える。

```text
不足率 = (目標字数 − 現在字数) ÷ 目標字数
```

| 不足率 | 手段 | 工程 |
|---|---|---|
| 許容帯の内側 | 増量しない | — |
| 許容帯の外〜10% 未満 | 解像度展開（描写・会話・感情の展開） | 規定量調整 |
| 10% 以上〜25% 未満 | 小さな子エピソードを 1 個追加 | 加筆工程（承認後） |
| 25% 以上〜50% 未満 | 子エピソードを複数追加 | 加筆工程（承認後） |
| 50% 以上 | エピソード構造自体が不足 → 再構成 | プロット段階へ差し戻す |

許容帯は [文章の伸縮操作規定](../../length_ops.md) の規定量調整で定める（既定 ±3%）。この表は、規定量調整が解像度展開で届かずに停止したとき、加筆工程で勧める手段の目安として使う。不足分をそのまま風景描写で埋めること（例：5000 字不足に 5000 字の描写）を防ぐための規定である。

### 子エピソードの目安字数

| 規模 | 目安 | 内部構造 |
|---|---|---|
| 小 | 親エピソードの 10〜15% | 目的と結果のみ明示、障害・判断は 1 文程度 |
| 中 | 親エピソードの 15〜25% | §4 の 4 要素をすべて場面化 |

この比率は目安であり、絶対字数は作品の平均的なエピソード密度に合わせて調整する。会話中心の文体では短め、描写中心の文体では長めに振れやすい。作品ごとに既存の子エピソード数本を実測し、基準値を上書きしてよい。

1 つの子エピソードが親の 25% を超える場合は、2 つに分割するか、§7 主従逆転を疑う。必要な子エピソード数は「不足字数 ÷ 子 1 個の目安字数」を切り上げて概算する。

### 再構成の範囲

不足率 50% 以上の場合、不足の分布によって再構成の単位を決める。

| 状況 | 再構成の単位 | 手段 |
|---|---|---|
| 不足が特定の親エピソードに集中 | 親エピソード単位 | 親を §2 で分解し直し、2 つ以上の親エピソードに分割する |
| 章全体で均等に不足 | 章単位 | 章のプロット段階に戻り、親エピソードを追加する |
| 作品全体で不足 | 作品単位 | 子エピソード増量では対応しない。プロット設計に差し戻す |

## 10. 挿入後の検証

| テスト | 判定基準 |
|---|---|
| 削除テスト | 持ち帰りのある子: 抜いても親の変化が成立するなら弱い。局所的効果だけの子: 抜くと読者が失う体感が、記録した局所的効果と一致するか |
| 変化テスト | 子の前後で何か一つでも変わっているか |
| 接続テスト | §5 のどの接続を満たすか明示できるか |
| 重複チェック | 他の子・本筋と運ぶものが被っていないか |
| 主従チェック | 親より目立っていないか |
| 強度チェック | 持ち帰りのある子: 追加した要素が後続で最低 1 回参照される、または登場人物の行動・判断に影響している。局所的効果だけの子: 局所的効果が具体的で、状態変化が場面内の行動・台詞に表れている（後続での参照は求めない） |

## 11. 記録フォーマット

子エピソードごとに、[文章の伸縮操作規定](../../length_ops.md)「子エピソード契約」の `child_episode` で記録する。運用時（特に AI 支援・複数人作業）は記録を推奨する。

| 区分 | 項目 | 理由 |
|---|---|---|
| 必須 | `operator` / `state_change` / `connections` / `carry_back` または `local_payoff` / `checks` | 接続義務（§5）と検証（§10）を追跡する最小限 |
| 任意 | `insert_at` / `est_chars` / `depth` | 配置・字数の管理用。記録負荷に応じて省略可 |
| 条件付き必須 | `order_note` | §3 の推奨順序から外れた場合のみ、その理由を記す |

親エピソードの分解結果は、次のように併記してよい。

```yaml
parent_episode:
  id: ep-03
  title: 王都へ行く
  analysis:            # §2 の分解結果
    goal: 王に謁見する
    obstacle: 弱い      # 薄い箇所をマーク
    result: 謁見の約束を得る
    change: 弱い
  target_chars: 6000
  current_chars: 4500
  shortage_rate: 0.25  # §9

child_episodes:
  - id: ep-03-a
    parent: ep-03
    operator: INTERRUPT
    insert_at: 序盤
    state_change:
      - kind: position
        who: 主人公一行
        before: 王都へ向かう途中
        after: 村で足止めされている
    connections: [障害を追加する]
    carry_back:
      - what: 村に滞在する理由
        used_at: ep-03-b
    est_chars: 700
    checks: { deletion: pass, change: pass, connection: pass, duplication: pass, dominance: pass, strength: pass }

  - id: ep-03-b
    parent: ep-03
    operator: DISCOVER
    insert_at: 中盤
    state_change:
      - kind: info
        who: 主人公
        before: 王都の状況を知らない
        after: 疫病が流行していると知る
    connections: [情報を追加する, 後続イベントの条件を作る]
    carry_back:
      - what: 王都の疫病
        used_at: ep-07    # 前倒し（§6）
    est_chars: 800
    checks: { deletion: pass, change: pass, connection: pass, duplication: pass, dominance: pass, strength: pass }
```
