# 流れ・山・オチの構造論（PEAK）

一般エピソード技法のうち、作品全体の構造を層に分けて診断する枠組み。索引は [episode_.md](episode_.md)。

> 原資料（来歴）: `C:/Users/Owner/Downloads/物語の山/flow-peak-payoff.md`（暫定仮説 v0.4。「流れ→山→オチ」のあるあるを、複数の生成モデルによる考察とレビューで整理したもの）

対になる葉は [episode_flow_break.md](episode_flow_break.md)（流れ破壊＝転の作り方）。本書が「どこが平坦か、何が回収されていないか」を見つけ、流れ破壊が「どこで何を壊すか」を作る。型どおりの配置（三幕構成・Save the Cat など）は [episode_golden_structure.md](episode_golden_structure.md)。

## Monogatari Coach での使い方

- **既定では読まない。** 物語の山・オチ・後味を設計するとき、または読後に平坦さや約束の回収漏れを診断するときに選ぶ。
- **プロットのアレンジの作業では、selected に無くても読む**（工程正本）。「平板なのでアレンジして」「プロットを変えて」などの依頼の手順は、計画 `_workingspace/plans/20261025_structure-theory-dosing.md` を参照。
- 層の名前（PROMISE・RHYTHM・FLOW・PEAK・PAYOFF・ENDING）と値（`mode: implicit`、`answer-type: substitute` など）は**設計層の語彙**である。`_meta.md`・`design_specification.md` の見出し・診断の記録に置き、物語案・あらすじ・章項の本文には「誰が何をした」で書く（`synopsis_presentation.md`）。
- 本モデルは**事後の診断**が主な使い道である（§1.1）。事前に全層を埋めない。
- 作品の既存の仕組みとの対応:
  - hidden の約束の**植え付け**（§3.5）は、`_meta.md` の伏線管理と同じものを指す。植え付けの箇所は伏線として記録してよい。
  - **texture-climax**（§5.3）は、読み進み感想（`reader_walk.md`）の反応の推移で検出される山（peak）を、読者側から実測した近い値として照らし合わせられる。同一視はしない（読み進みはペルソナ一人の反応である）。
  - 平坦の検査（§13）は METRON の計測とは別物である。

## 0. 元のあるある

物語は、出来事が順に続く「流れ」だけでは弱くなりやすい。
流れの中で問題・感情・選択・損失などを積み上げ、それらが無視できなくなる地点を「山」とする。
最後に、冒頭で示された欲望・問い・関係・思い込みなどに何らかの答えを返し、「オチ」として物語の意味を確定する。
原則は「流れ→山→オチ」だが、怪談・日常・雰囲気物など、意図して山やオチを弱める型も例外として認める。

あわせて、次の補足がある。

> オチがないことをオチにしてよい。途中が楽しければよい。
> 起承転結がはっきりしていなくてもよいが、何かしらの持ち味の緩急はつけてほしい。

## 1. 中心仮説

> **物語は、何かを揺らし、必要なら積み上げ、どこかで決済し、必要なら意味を確定し、最後に後味を残す。**

| 要素 | 必須度 | 位置づけ |
|---|---|---|
| 変調（緩急） | **既定で必須** | 作品の持ち味が寄せては引く。外す場合は意図した形式として明示する |
| 山 | 推奨 | 積み上げが決済を求める地点。規模は極小でもよい |
| オチ | 任意 | 意味の確定。明示・暗黙・確定しない、のいずれもあり得る |

- 起承転結がはっきりしている必要はない。
- 骨格は「共通の出汁」であり、料理そのものではない。何を約束し、何を揺らし、何で決済し、何を回収し、どんな後味を残すかは、作品ごとに選ぶ変数である。
- 本書は物語の記述であると同時に、創作・生成のための規範として書く。

### 1.1 運用指針

> **本モデルは主に事後の診断とレビューに使う。事前に埋めるテンプレートではない。**

- 書く前に全層を埋めようとすると、「計算された回収」が先に立ち、偶然や余白が削がれやすい。
- 推奨する使い方:
  - **事前**: PROMISE と texture-axis だけを軽く決める（何を期待させ、どんな味で進むか）。
  - **事中**: 層を意識せず書く。
  - **事後**: 各層に照らして診断する。平坦な区間、回収されていない main の約束、植え付けのない hidden の約束などを探す。
- 層の値は作品を説明する語彙であり、埋めなければならない欄ではない。空欄があっても、それだけでは失敗ではない。

## 2. 全体像

```text
PROMISE   何を期待させるか
RHYTHM    何が寄せては引くか（持ち味の変調）
FLOW      何が次を生むか
PEAK      どこで積み上げが決済を求められるか
PAYOFF    何を回収し、どう答えるか
ENDING    どんな後味を残すか
```

時間順に並べると次のようになる。

```text
PROMISE → RHYTHM / FLOW → PEAK → PAYOFF → ENDING
```

- RHYTHM と FLOW は並走する。FLOW が出来事を前に進め、RHYTHM がその手触りを揺らす。
- 各層は作品全体だけでなく、章・場面の単位でも成り立つ（→ 4. 入れ子構造）。

## 3. PROMISE（約束）

### 3.1 定義

> 読者が「この話ではこれが起こる／こう進む」と期待する対象。

PAYOFF の強さは、回収そのものよりも、**事前にどれだけ約束されていたか**に大きく左右される。

### 3.2 二種類の約束

| 種類 | 内容 | 例 |
|---|---|---|
| event-promise | 何かが起こる・決着するという約束 | 魔王を倒す／この二人はどうなる／犯人は誰か／この違和感の正体は何か |
| texture-promise | この作品はこういう味で進むという約束 | 笑える／居心地がいい／ずっと不穏 |

- event-promise は PAYOFF の target の候補になる。
- texture-promise は RHYTHM の texture-axis を予告する。

### 3.3 構成要素

```text
PROMISE
  kind:         event | texture
  object:       何を約束しているか
  visibility:   declared | hidden
  rank:         main | sub
```

- **declared**: 冒頭や途中ではっきり示された約束。
- **hidden**: 作中ではっきり示されていないが、物語が実は扱っている約束。
- **main**: 物語全体が回収を負っている約束。
- **sub**: 物語の厚みを出す副次の約束。

### 3.4 rank の扱い

| rank | 回収されない場合 |
|---|---|
| main | 意図した `mode: none` でなければ失敗（約束の不履行） |
| sub | 失敗としない。余韻・世界の広がりとして残してよい |

- main の約束は、原則として作品に一つ（多くても少数）とする。
- sub の約束は、入れ子構造の下の階層（章・場面）で回収されることが多い。
- 上の階層の sub が、下の階層では main になることがある（作品全体では sub の約束が、ある章では main になる）。

### 3.5 ずらしと植え付け条件

> **ずらしとは、declared の約束ではなく、hidden の約束を回収すること。**

例:「恋を叶えたい」（declared）を追う物語が、最後に「自分の足で立てるか」（hidden）を回収する。

- hidden の約束は、読後に振り返って「確かに最初からそれを扱っていた」と納得できる必要がある。
- 読後の納得そのものは事前に保証できない。そこで、構造上の代わりの目印として**植え付け条件**を置く。

> **植え付け条件: hidden の約束は、回収の前に、作中で複数回その約束に触れる描写がなければならない。**

```text
PROMISE
  visibility: hidden
  plants:     回収の前にその約束に触れる描写の箇所（複数）
```

- 植え付けは、はっきり言及する必要はない。行動・小道具・繰り返すモチーフなどでよい。
- 植え付けが足りなければ、それは「ずらし」ではなく「問いのすり替え」または「植え付けなき回収」（→ 12. 失敗パターン）になる。
- 必要な回数は暫定で「複数」とし、具体的な閾値は未決とする（→ 14）。

## 4. 入れ子構造

本モデルの各層は、作品の各階層で部分的に成り立つ。

```text
作品
 ├─ 章
 │   ├─ 場面
 │   │   └─ 会話・ビート
```

ここから次の二つが説明できる。

- **大きな PAYOFF がなくても、小さな PAYOFF が続いていれば読める。** 全体の `mode: implicit` や `mode: none` は、場面単位の山とオチが支払っている。
- **大きな PEAK があっても、途中の小さな RHYTHM が死んでいれば読みにくい。**

その他:

- 多層の山や、思い込みの回収を遅らせる操作は、この階層の間の操作として説明できる。
- 連載で毎話の「引き」が効くのは、話単位の PROMISE と PAYOFF が入れ子になっているため。

## 5. RHYTHM（持ち味の変調）

### 5.1 定義

> **RHYTHM = texture-axis の上で起きる振れ幅・周期・向きの変化**

「緩急」は説明用のラベルとして使う。実際に扱うのは速い・遅いではなく、**作品の主な感覚の軸がどう変わるか**である。恋愛の変調は「速い→遅い」ではなく「近づく→離れる→近づく」である。

```text
RHYTHM
  texture-axis   何が変化するか（作品の持ち味）
  amplitude      どれだけ振れるか
  period         どの間隔で振れるか
  direction      どちらへ動くか（寄せ／引き、接近／離反など）
```

### 5.2 texture-axis の例

| 作品の型 | texture-axis | 寄せ | 引き |
|---|---|---|---|
| サスペンス・バトル | 緊張 | 危機・衝突 | 安堵・準備 |
| コメディ | 笑いの密度 | ボケの畳みかけ | 間・日常の描写 |
| 日常系 | 居心地 | 和やかさ・賑やかさ | ちょっとした寂しさ・静けさ |
| 怪談 | 違和感 | ずれた一行・異物 | ふつうの描写 |
| 会話劇 | テンポ | 応酬 | 沈黙 |
| 恋愛 | 距離 | 接近 | 離反・すれ違い |
| 雰囲気物 | 情感・イメージの濃さ | 濃い描写 | 余白 |

- 持ち味の軸は一本とは限らない。複数の軸がずれて揺れると、変調に厚みが出る。
- texture-axis は texture-promise と一致しているべきである。

### 5.3 texture-climax

> **texture-climax = texture-axis の上で、振れ幅が作品中で最大になる地点**

- texture-climax は感情の頂点であり、構造上の山である PEAK（→ 7）とは別物として扱う。
- 一致することも多いが、しないこともある。

| 関係 | 例 | 効果 |
|---|---|---|
| 一致 | 最大の敵との決戦が、最も緊張する場面でもある | 王道の盛り上がり |
| climax が先 | ホラーで最も怖い場面は中盤、構造上の山は終盤の「扉を開けるか、逃げるか」 | 恐怖の記憶が決済の場面に重みを与える |
| PEAK が先 | 決断の場面は静かで、そのあとの結果の場面で感情が最大になる | 決断の重さが遅れて届く |

- 診断では、両者を別々に特定し、距離と順序を確かめる。

### 5.4 変調を外す場合

ほとんど動かない静物的な作品、実験的な作品、観察記録のような作品では、変化がほとんどないこと自体を狙う場合がある。その場合は、意図した形式として明示する。

```text
RHYTHM
  texture-axis: none
  intent: deliberate
```

## 6. FLOW（流れ）

### 6.1 定義

> 出来事を次の出来事へつなぎ、PEAK でぶつける材料を積む層。

- 流れが弱くなる原因は、出来事が「そして／それから」でつながる**並べただけの連鎖**にある。
- 積み上げは軸ごとに起きる。主な軸は問題・感情・選択・損失・関係・情報。

### 6.2 つなぎ方の三種

| link-type | つなぎ | 働き |
|---|---|---|
| causal | だから | 前の出来事が次を生む |
| adversative | しかし | 予測や意図が裏切られる |
| reinterpret | その結果、意味が変わった | あとの出来事が、前の出来事の意味をさかのぼって書き換える |

```text
Aが起こる
↓ causal
だからBになる
↓ adversative
しかしCが起こる
↓ reinterpret
その結果、Aの意味が変わる
```

- reinterpret はミステリー・恋愛・心理劇でとくに大事になる。
- reinterpret は PAYOFF の answer-type「反転」や、target「思い込み」と結びつきやすい。
- adversative と reinterpret を意図して作る操作が、[流れ破壊](episode_flow_break.md)である。

### 6.3 出来事の順と見せる順

```text
FLOW
  order: story | presentation
```

| order | 内容 | 扱うもの |
|---|---|---|
| story | 作中の世界で出来事が起きた順 | 何が何を生んだか（causal / adversative） |
| presentation | 読者に見せる順 | 何をいつ見せるか（回想、時系列の入れ替え、語り手の切り替え） |

- 一直線の物語では、二つの順は一致する。
- 一直線でない物語では、二つの順がずれる。そのずれ自体が道具になる。
- **reinterpret の多くは、見せる順から生まれる。** あとで見せた情報が、前に見せた場面の意味を書き換える。
- PEAK・texture-climax・PAYOFF の位置は、**見せる順の上で**測る。読者が体験するのは見せる順だからである。
- 積み上げの因果（causal）は、出来事の順で成り立っていればよい。見せる順では、結果が原因より先に出てもよい。

**多視点構成**: 複数の語り手が並行する場合、FLOW は語り手ごとに並走する。並走する FLOW の合流点は PEAK の候補になりやすい。扱いは未決（→ 14）。

## 7. PEAK（山）

### 7.1 定義

> **PEAK = それまでの積み上げが決済を求める地点**

- 複数の積み上げの軸が一点で重なり、それまでの**先送りができなくなる**。
- 多くの場合、選択を迫られ、その選択で人物があらわになる。
- 多くの場合、RHYTHM の振れ幅も大きくなる。ただし **texture-climax と PEAK は一致するとは限らない**（→ 5.3）。
- 推奨要素であり、規模は極小でもよい（日常系の「小さな決心」など）。

### 7.2 構成要素

```text
PEAK
  pressure-type        何が決済を求めているか
  trigger              何をきっかけに先送りできなくなるか
  irreversible-change  何がもう元に戻らなくなるか（none 可）
```

**pressure-type の例**

| pressure-type | 決済を求めるもの |
|---|---|
| danger | 危険・命の脅威 |
| emotion | 感情の圧 |
| choice | 選択の圧 |
| revelation | 情報量・真相の露見 |
| misunderstanding | 誤解 |
| loss | 失うかもしれないこと |
| ethics | 倫理の葛藤 |
| irreversibility | 戻れなさ |
| relationship | 関係の緊張 |

**ジャンル別に山になるものの例**

| 型 | 山になるもの |
|---|---|
| バトル | 最大の敵との決戦 |
| 恋愛 | 告白・拒絶・別れ・選択 |
| ミステリー | 真相の露見 |
| ホラー | 正体を知る、逃げ場が消える |
| 日常 | 小さな決心、関係の変化 |
| コメディ | 誤解・嘘・状況の一斉崩壊 |
| 政治劇 | 利害関係者を巻き込んだ決断 |
| 成長譚 | 以前ならできなかった選択 |
| 怪談 | 理解できないものへの最接近 |

## 8. PAYOFF（オチ）

### 8.1 定義

> **PAYOFF = 物語が扱っていた約束に、意味の確定を与える地点**

- **結末とオチは別物。**
  - 結末: 事態が終わること
  - オチ: 意味が確定すること
- 事件が解決しても約束に答えていなければ、オチにならない。
- 事態が未解決でも約束に答えていれば、オチは成り立つ。

### 8.2 構成要素

```text
PAYOFF
  mode         explicit | implicit | none
  target       どの PROMISE を回収するか
  answer-type  どう答えるか（論理の関係）
  consequence  答えの結果、何が残り何が失われるか
```

### 8.3 mode（回収のしかた）

| mode | 内容 | 例 |
|---|---|---|
| explicit | 作中で意味がはっきり確定する | 犯人が明かされる、二人が結ばれる |
| implicit | はっきりとは示されないが、読後に意味が確定する | 何も解決しなかったが、この時間そのものがよかったと伝わる |
| none | 意味を確定しない | 断章、実験的な作品、意図した投げ出し |

- あるあるの「オチがないのがオチ」は、本モデルでは **implicit** にあたる。
- **none が成り立つ条件**
  - 意図した形式として選ばれていること（→ 12「約束の不履行」と区別する）。これは常に要る。
  - ふつうのオチなし作品では、次の二つが読者を支える。欠けていれば「支払いのない none」（→ 12）を疑う。
    - RHYTHM に持ち味の変調があること。
    - 場面単位の小さな山とオチが、読者を運び続けていること。
  - **変調も山も意図して外す形式**（ほとんど動かない静物的な断章など。RHYTHM `texture-axis: none, intent: deliberate`、→ 5.4）は、上の二つの支えを求めない。その形式を選んだことと、何を読者に残すつもりか（ENDING の tone）を記録すれば成り立つ。

### 8.4 target（回収の対象）

| target | 例 |
|---|---|
| question | 何が起きたのか |
| desire | 主人公は望みを得られるか |
| misbelief | 思い込みは解けるか |
| vow | 交わした約束は果たされるか |
| relationship | この二人はどうなるのか |
| situation | 世界・共同体はどうなるか |
| theme | 教訓・命題（昔話の「欲張るとひどい目にあう」など） |
| goal | 目的地へ着けるか |
| experience | この時間・過程そのものに価値があったか |

### 8.5 answer-type（答えの論理の関係）

| answer-type | 日本語 | 形 |
|---|---|---|
| affirm | 肯定 | やはりXだった |
| negate | 否定 | Xだと思っていたが違った |
| invert | 反転 | 求めていたXこそが問題だった |
| substitute | 代替 | Xは得られなかったがYを得た |
| trade | 代償 | Xを得たがZを失った |
| return | 回帰 | 元の状態へ戻ったが意味が変わった |
| defer | 保留 | 約束を立てたうえで、答えを留める |
| recur | 再発 | 終わったと思ったが終わっていない |

- answer-type は**論理の関係**だけを扱う。感情の後味は ENDING で扱う。
- 最も強くなりやすいのは**ずらし**（hidden の約束の回収、→ 3.5）。answer-type では invert や substitute になりやすい。

### 8.6 例

```text
PROMISE
  kind: event / object: 二人の恋の行方 / visibility: declared / rank: main
  kind: event / object: 主人公の自立 / visibility: hidden / rank: main
    plants: 一人で決められない場面、親の言葉の繰り返し、使われない鍵

RHYTHM
  texture-axis: 距離

PEAK
  pressure-type: relationship
  trigger: 秘密の露見
  irreversible-change: 信頼の崩壊

PAYOFF
  mode: explicit
  target: desire（hidden の約束: 自立）
  answer-type: substitute
  consequence: 恋を失い、自立を得る

ENDING
  tone: bittersweet
```

```text
# オチなしの日常回の例
PROMISE
  kind: texture / object: 居心地のよさ

RHYTHM
  texture-axis: 居心地

PEAK
  pressure-type: relationship
  trigger: 小さな言い合い
  irreversible-change: none

PAYOFF
  mode: implicit
  target: experience
  answer-type: affirm

ENDING
  tone: warm
```

```text
# 意味を確定しない断章の例
# 廃線跡を歩く人物の、断片的な観察が並ぶ短編
PROMISE
  kind: texture / object: 静かな喪失感 / rank: main

RHYTHM
  texture-axis: 情感・イメージの濃さ
  （濃い描写と余白が交互に来る）

PEAK
  pressure-type: emotion
  trigger: 錆びた駅名標に、かつての町の名前を見つける
  irreversible-change: none

PAYOFF
  mode: none
  （なぜ歩いているのか、何を失ったのかは最後まで確定しない）

ENDING
  tone: hollow
```

- `mode: none` でも ENDING は成り立つ。意味は確定しないが、感情のトーンは読後に残る。
- この例は event-promise を持たず texture-promise だけを約束しているので、「約束の不履行」にならない。

## 9. ENDING（後味）

### 9.1 定義

> **ENDING = 物語を閉じたときに残る感情のトーン**

- answer-type（論理の関係）とは別に選べる。
- 同じ PAYOFF でも、ENDING で別の作品になる。

```text
PAYOFF: 復讐には成功した     → ENDING: 虚無
PAYOFF: 恋は実らなかった     → ENDING: 爽やか
PAYOFF: 主人公は故郷を守った → ENDING: 大団円／苦い勝利／不穏
```

### 9.2 tone の例

| tone | 後味 |
|---|---|
| triumphant | 大団円 |
| bittersweet | 苦い勝利・ほろ苦さ |
| ironic | 皮肉 |
| quiet | 静かな余韻 |
| uneasy | 不穏 |
| cyclical | 巡り続ける感じ |
| warm | 温かさ・もう少し見ていたい |
| hollow | 虚無 |
| refreshing | 爽やか |

- PAYOFF の `return`（回帰）と ENDING の `cyclical` は別物として扱う。return は論理として元の状態へ戻ること、cyclical は巡り続けるという感じが残ること。
- `mode: none` の作品にも ENDING はある。

## 10. locus（変化と気づきの場所）

### 10.1 二つの次元

```text
change-locus:      character | relationship | world | none
perception-locus:  character | reader
```

| パラメータ | 問い | 例 |
|---|---|---|
| change-locus | **何の状態が変わるか** | 主人公が変わる／関係が変わる／世界の見え方が変わる／何も変わらない |
| perception-locus | **誰の中で積み上げと回収が起こるか** | 登場人物が気づく／読者だけが気づく |

分けることで、次のような組み合わせを表せる。

- 関係が変わり（change: relationship）、それを読者だけが知っている（perception: reader）。
- 主人公は変わらないが（change: world）、世界の見え方が変わる。

### 10.2 例外とされてきた型の読み直し

| 型 | 読み直し |
|---|---|
| 怪談 | texture-axis は違和感。PEAK は理解できないものへの最接近。answer-type は recur、tone は uneasy。perception-locus は reader に寄りやすい |
| 日常系 | texture-axis は居心地。PEAK は極小。mode は implicit、target は experience、answer-type は affirm または return |
| 雰囲気物 | texture-axis は情感・イメージの濃さ。perception-locus は reader。mode は implicit または none |

> これらは例外ではなく、PEAK と PAYOFF を小さく置き、気づきの場所を読者側に置いた、ふつうの作品である。

## 11. ジャンルは「型」ではなく「重み」

ジャンルは型を決めるものではなく、選択の**偏り**として扱う。

> 以下の重みは説明用の仮の値であり、統計ではない。

```text
# 恋愛
pressure-type:
  relationship: high
  choice:       high
  loss:         medium
  danger:       low

# ホラー
pressure-type:
  danger:          high
  revelation:      high
  irreversibility: high
  relationship:    low
```

- こうすると、ジャンルらしさは保ちながら、毎回同じ展開になるのを避けられる。
- texture-axis、answer-type、tone も同様に、ジャンルごとの重みとして持てる。

## 12. 失敗パターン

| 層 | 失敗 | 症状 |
|---|---|---|
| RHYTHM | **平坦** | 持ち味が同じ強さで流れ続け、寄せも引きもない。意図した形式として明示されていなければ、最も根本的な失敗（明示したもの＝5.4 は失敗に数えない） |
| RHYTHM | 軸の取り違え | 持ち味と関係ない軸（日常系に無理な緊張など）で変調をつけ、作品の味を壊す |
| PROMISE | 味の約束違反 | texture-promise と実際の texture-axis が食い違う。ただし、序盤でほのめかしを置いたうえで意図して作品の約束を書き換えるもの（[流れ破壊](episode_flow_break.md) 2-13 の作品契約の破壊）は失敗に数えない |
| PROMISE | 約束の不履行 | rank: main の event-promise をはっきり示したのに回収しない。意図した `mode: none` とは区別する。sub の未回収は失敗としない |
| PROMISE | 植え付けなき回収 | hidden の約束を、回収の前に一度も（または一度しか）触れずに回収する |
| FLOW | 並べただけの連鎖 | 出来事の記録になり、積み上げが起きない |
| PEAK | 積み上げなき山 | 唐突なクライマックスになり、重みがない |
| PEAK | 早すぎる山 | 後半が消化試合になる |
| PAYOFF | 問いのすり替え | 回収した約束が、読後に振り返っても物語が扱っていたと納得できない |
| PAYOFF | 説明しすぎ | 意味を確定しすぎて、読後の余地がなくなる |
| PAYOFF | 結末だけでオチがない | 事件は終わったが、何の話だったかが残らない |
| PAYOFF | 支払いのない implicit / none | 全体のはっきりした回収を省いたのに、途中の山とオチも弱い。ただし、変調も山も意図して外す形式（5.4 の `texture-axis: none, intent: deliberate` と併用し、記録したもの）は失敗に数えない |
| 全体 | 画一化 | 問題→強敵→覚悟→勝利→成長の繰り返しになる |

> 「オチがない」こと自体は失敗ではない。
> **オチがあっても途中が平坦なら弱く、オチがなくても変調があれば成り立つ。**

## 13. 生成の制御（物語論とは別の層）

- 直近の生成で使った PEAK と PAYOFF の組み合わせは、次の選択の確率を下げる。直近で「正体露見 × 自己犠牲」を使ったら、次はその組み合わせを出にくくする。
- 変調の検査は、生成後の点検項目として持てる。場面ごとに texture-axis の強さを見積もり、一定の区間変化がなければ平坦と判定する。
- PROMISE と PAYOFF の対応の検査も持てる。rank: main の event-promise ごとに、回収されたか、意図して none とされたかを確かめる。
- 植え付けの検査も持てる。hidden の約束を回収している場合、回収の前にその約束に触れる描写が複数あるかを確かめる。
- PEAK と texture-climax の位置の検査も持てる。両者を見せる順の上で特定し、距離と順序を報告する。
- いずれも事後の診断として使う（→ 1.1）。
- これらは構造論ではなく生成側の設計として、モデルとは切り分けて持つ。作品ごとの確率の振り方（黄金律・ばらつき・診断のみ・形式として外す）は計画 `_workingspace/plans/20261025_structure-theory-dosing.md` で扱う。

## 14. 未決の論点

1. **ジャンルの重みは記述か処方か**: 既存作品の分析に使うのか、生成の初期値に使うのかで、値の意味が変わる。
2. **perception-locus の中間**: 一人称の語りや信頼できない語り手のように、登場人物と読者の両方で回収が起こる場合の扱い。
3. **変調の最低の振れ幅**: どの程度振れれば「平坦ではない」と言えるか。静かな作品ほど判定が難しい。
4. **変調の周期**: 寄せと引きの間隔が規則的すぎると、それ自体が単調になる。周期の揺らぎの扱い。
5. **main の約束が複数ある場合**: 群像劇や二人主人公で、回収の順序や重みをどう扱うか。
6. **reinterpret と invert の境目**: 途中での意味の書き換えと、最後の意味の反転は連続している。どこで区切るか。
7. **`mode: none` の実在範囲**: 本当に何の意味も確定しない作品はどこまであるか。多くは implicit に回収されているのではないか。
8. **植え付けの閾値**: hidden の約束の植え付けは何回、どの間隔で要るか。作品の長さや約束の意外さとの関係。
9. **一直線でない構成**: 見せる順が大きく乱れる作品で、積み上げがどう成り立つか。読者の中で出来事の順を組み立て直すこと自体が、積み上げの一種になっている可能性がある。
10. **多視点構成**: 複数の FLOW が並走する場合、PEAK は合流点に一つ置くのか、語り手ごとに置くのか。
