# 案とあらすじの見せ方（設計層と提示層）

> 型は裏で使う。利用者に見せるのは話だけ。

---

## Monogatari Coach での使い方

「一からストーリーを出して」「〇〇ものの話を考えて」などの物語案、`proposal.md` のログライン・あらすじ・キャラクター紹介、チャットモードのあらすじと選択肢、`design_specification.md` の章構成を書くときに、出す前に読む。Gate B4 の口語化でも同じ葉を使う。本文の執筆・清書では通読しない。型名遮断を体位・体勢の伏せと誤読しそうなときだけ、「型名と体位・体勢」を読む。カタログ短縮が本文に残ったときの入口は `rewrite.md`。上記以外では読まない。
ジャンル葉や技法の葉を読んだ直後は、型名・ID・手順のあだ名がそのまま案に漏れやすい。それを防ぎ、設計で決めたことを人物・出来事・選択に置き換えて見せるための基準である。章項も同じ文の形で書く。

| 出力 | 層 | 書いてよいもの |
|---|---|---|
| チャットで出す物語案・あらすじ・候補案・選択肢 | 提示層 | 人物、状況、出来事、選択、結末、場面 |
| `proposal.md` のログライン・あらすじ・キャラクター紹介の欄 | 提示層 | 同上 |
| `design_specification.md` の章構成の各項 | 提示層と同じ文の形 | 誰が何をしたかの口語。型名・深度は見出し側。体位・体勢は伏せない |
| 本文（`_novel_text/`） | 提示層 | 人物、状況、出来事、選択、結末、場面（構造の実況を書かない。体位・体勢は伏せない） |
| `_meta.md`（Gate B 記録など）、`design_specification.md` のテーマ・コンセプト・見出し・相関図、`character.md` / `world.md` の欄名、`config.md` のジャンル・キーワード欄、`proposal.md` の魅力・ターゲット層の欄 | 設計層 | 型名、ジャンル葉の名前、ID、決定表、理論名、構造の説明、点検の欄名 |
| `character.md` / `world.md` の説明文、`config.md` のログラインと執筆方針、`_meta.md` の外部紹介文 | 提示層と同じ口語 | だれが何をしたか。欄名は残す。作家用のあだ名は翻訳する |
| 作業報告（Gate B 完了報告など） | 提示層ではない | 設計の情報を書いてよい。ただし案・あらすじとは別の節に分ける |
| 評価・監査（下読み・Editor Score・一貫性監査・読み進み） | 対象外 | 構造を語って評価してよい |

型名を見せられた利用者は、叩き台ではなく設計図を読まされる。設計図には否定の手がかりがなく、「知らんがな」で止まる。利用者が「この兄はいらない」と言える形で出す。

---

## 1. 原則

- **語彙の遮断**: 提示層に、型名・ジャンル葉の名前・ID・理論名・フレームワーク名を書かない。葉の見出し語・手順のあだ名・検査ラベル（カタログ短縮）も書かない。詳細は「カタログ短縮と口語化」。
- **型名と体勢は別**: 遮断するのは型名・ID・深度Lvである。体位・体勢・行為の具体（向き、脚の畳み、挟み、圧）を伏せることではない。詳細は「型名と体位・体勢」。
- **翻訳の義務**: 設計の決定は、提示層では具体的な人物・出来事・選択として現れなければならない。ラベルの言い換えは翻訳とみなさない。
- **あらすじの形**: 「誰が、どういう状況で、何を賭けて、どうなるか」が読める文章で書く。部品の列挙で書かない。
- **開示は求めに応じて**: 設計の内訳は、利用者が明示的に求めたとき（「この案の設計を見せて」など）だけ、提示層とは別の枠で出す。
- **否定は話の語で受ける**: 利用者の否定は「この兄はいらない」のような話の言葉のまま受け取り、内部で設計の決定に対応づける。利用者に型名や決定欄の名前で否定させない。

## 1.5 型名と体位・体勢

遮断するのはジャンル葉の型名・ID・深度Lvである。体位・体勢・行為の具体を、あらすじ・章出来事・本文から伏せることではない。

対象は物語案、`proposal.md` のあらすじ、`design_specification.md` の章出来事、本文（`_novel_text/`）である。

「型名を出さない」を「脚の向きや圧のかけ方を書かない」と読まない。後者は翻訳の義務であり、A2（ぼかし言い換え）になる。

**不合格（伏せ）**

> 二人の手当てが進み、関係が深まる。
> 次の型へ移る。

**合格**

> 亮介は葵の両膝を胸元へ畳み、上から体重をかけて圧す。

カタログ名だけで済ませるのも不合格である。「正常型」「Lv.4」は見出しまたは `_meta.md` に置き、項と本文では誰が何をしたかで書く。

この節は小説の提示層の話である。漫画ページ YAML の `scene.location_en` に体位の連鎖を書くな、は `_how_to.example/manga.md` の別禁則であり、ここでの対象外である。体勢はコマの `prompt_tags` と `pose_action_en` へ置く。

## 1.6 カタログ短縮と口語化

遮断するのは型名・IDだけではない。葉の見出し語、手順のあだ名、検査ラベルを提示層の文に置くのも不合格である。

- **作家用のあだ名**: 葉を読んだ側だけが知る短縮。提示層では「だれが、どこまで、何をしたか」に翻訳する。
- **世界の言葉**: 作中の人が実際に言う呼び名は残してよい。初出で意味が聞こえるようにし、説明なしでは連発しない。
- **点検の欄名**: `character.md` のボディー子ラベル、`未使用膜`、章の `**分量目安**` 行は残す。欄の右側の説明文だけ口語にする。

初回の設計では、抜けを防ぐためあだ名で厚くしてよい。事実が固定したあと（Gate B4 の口語化）で、提示層の文を直す。出来事・所持品・関係は変えない。作品固有の対訳は、その作品の `config.md` 執筆方針に閉じ、この葉へ上げない。

手順の正本はスキル `novel-planning` の B4。本文全章のあとで通す工程ではない。清書は `rewrite.md` であり、企画の口語化とは別である。

**不合格（A7）**

> 四の夜は傘頭だけ。着地は外。寸止め。

**合格**

> 亮介は傘の先だけを入り口へ沈めて、中へは進まない。白い熱は外へ出す。途中で止める。

## 2. 反パターン

| ID | 反パターン | 例 |
|---|---|---|
| A1 | 部品表あらすじ | 「断罪回避型 × 前世知識 × 友情主軸」と型や要素を並べる |
| A2 | ぼかし言い換え | 型名を伏せただけで抽象のまま残す。「立場の逆転を軸にした成長の物語」 |
| A3 | 解説付きあらすじ | 「本作は〜を描く」「テーマは〜である」と作品の意図を外から説明する |
| A4 | 構造の実況 | 「ここで第一の転換点が訪れ」と、設計上の位置を本文や筋書きに書き込む |
| A5 | 決定の宙吊り | 「〜するかもしれない」「〜か、あるいは〜」と選択を保留する。設計で決めたことは提示層でも決まっていなければならない |
| A6 | 主語のない体言止め | 「狭い教室。音だけになる」「めくり。」と、誰が何をしたかが聞こえない |
| A7 | カタログ短縮のまま | 「着地」「寸止め」など、葉のあだ名だけで項を済ませる |

この表の ID（A1〜A7）も設計層の語であり、利用者に出す案には書かない。

## 3. 例

**不合格（A1・A3）**

> 悪役令嬢もの／断罪回避型。前世知識あり、恋愛弱め・友情強め。主人公の再定義と評価の逆転を描く。

**合格**

> 婚約破棄の場で、令嬢エルザは反論せずに一枚の帳簿を差し出した。王太子の側近が三年間横領してきた記録だった。断罪は保留になったが、彼女が守ったのは自分の名誉ではなく、帳簿をつけ続けてくれた侍女の職だった。

合格例では、「断罪回避」「実務家の主人公」「友情主軸」がいずれもラベルではなく行動として現れている。どの型をどの行動に置き換えたかは、`_meta.md` の Gate B 記録（提示層での現れ）に書く。

### キャラクター紹介

**不合格**

> セリア：ツンデレ職人ヒロイン。主人公の翻訳役で、出自の秘密を持つ。

**合格**

> セリア（17）：亡き親方の工房を一人で守る鍛冶師。口は悪いが、凍える村人の修理を断れずに借金を重ねてきた。よそ者の技師の理屈を、職人の手の言葉に置き換えて村に広めていく。

人物の役割の名前（翻訳役、ワトソン役、ツンデレなど）や `character.md` のラベル名は設計層の語である。紹介では、その人物が何をし、何を望み、誰とどう関わるかで書く。

複数の案を出すときも、案ごとにこの形で書く。案の見出しに型名を付けない（「案1：断罪回避型」ではなく「案1：帳簿を差し出す令嬢」）。

## 4. 出す前の検査

| 検査 | 内容 | やり方 |
|---|---|---|
| 語彙検査 | 型名・ジャンル葉の名前・ID（例: `A1`、`F2`、`X7`、`genre/…`、`〇〇型`）が提示層にないか | 読んだ葉の見出し・表の型名と照らして目で確かめる |
| カタログ短縮検査 | 読んだ葉の見出し・手順名・あだなが、ログライン・あらすじ・章項・紹介・人物と世界の説明文に残っていないか | 残してよいのは世界の言葉（初出で意味を示す）と点検の欄名。作家用のあだ名は「だれが何をしたか」へ直す |
| 対応検査 | 設計で決めた型・決定の一つひとつについて、提示層の本文中で対応する一文を指せるか | 指せない決定は翻訳されていない。Gate B 記録の「提示層での現れ」に書けるかで確かめる |
| 門外漢検査 | ジャンルや型の知識がない読者が、あらすじだけで話の筋と結末を説明できるか | 型名を知らない人に読ませるつもりで、筋と結末を一文で言い直せるか確かめる |
| 主語検査 | 各文・各章項に人物が主語としてあるか | 主語が風景・音・身体部位だけの項は直す |
| 声検査 | 読み上げて、誰が何をしたかが聞こえるか | 体言止め・「めくり」だけで場面が浮かばなければ直す |
| 体勢検査 | 行為・体勢を「手当てが進む」だけで済ませていないか | 誰がどの向きで何をしたかを指せるか。伏せは A2 |

## 5. 設計の内訳を見せるとき

利用者が「この案の設計を見せて」「どの型を使ったの？」と求めたときは、案の本文とは別の節で出す。

```text
（案の本文）

---
設計の内訳（求めに応じて）
- 使ったジャンル資料: …
- 型と、案の中での現れ: 断罪回避 → 帳簿を差し出して断罪を保留させる
```

求められていないときは、この節を付けない。

## 6. 章出来事（設計書のあらすじ）

`design_specification.md` の章構成は設計層の置き場である。テーマ・コンセプト・見出しは設計層の語を置いてよい。各番号の本文は提示層と同じ文の形で書く。利用者が「この項はいらない」と言える手がかりを残す。

章項はあらすじの種である。先に章項を書き、そこから `proposal.md` の連続文あらすじを圧縮する。型名は `_meta.md` の「提示層での現れ」にだけ残す。

- 各項は「誰が、何をしたか」が聞こえる口語1文とする。台詞を含めてよい。
- 体言止め、場面の音だけ、「めくり」「着地」のようなラベル、カタログ語だけで済まない。詳細は「カタログ短縮と口語化」。
- 主語は人物名（または呼び方）を書く。風景や身体の一部だけを主語にしない。
- 体位・体勢は伏せない。詳細は「型名と体位・体勢」。

**不合格（A4・A6）**

> 1. 狭い教室。チョークの音だけになる。
> 2. ここで第一の転換点が訪れる。
> 3. めくり。帳簿を差し出したまま、場が止まる。

**合格**

> 1. エルザは教室の後ろの席に座り、チョークの音だけが残るなか帳簿を膝に置く。
> 2. エルザは反論せず、一枚の帳簿を差し出す。
> 3. 帳簿を差し出したまま、エルザは下がらない。場が止まる。

主語が落ちて音と物だけが残る書き方も同じ不合格である。

**不合格**

> 狭いユニットバス。給湯の音と、脱いだ制服がフックに掛かる音だけになる。

**合格**

> 亮介が給湯をひねると、狭いユニットバスに湯の音だけが残る。葵は制服を脱いでフックに掛ける。
