# 世界設定の用語集（world.md の `## 用語`）

作品固有の名前と概念を `world.md` の用語集に定義し、本文・あらすじ・設計書で同じ意味で使うための書き方と、用語照合（検査）の基準。

既定では読まない。次のときだけ読む。

- `world.md` を作る・用語を足すとき（企画の Gate A / Gate B、Gate B の外での設定改稿）
- 起草・清書で、作品固有の新しい名前や仕組みを書きたくなったとき
- 用語照合（`_reader/terminology_YYYYMMDD_HHMM.md`）を行うとき

## 1. 考え方

- 用語集は作品固有の名前の正本である。制度・能力・技術・現象・役職・分類・場所・組織・物など、作品の中だけで意味を持つ名前を置く。
- 発明そのものは悪ではない。作品の手触りになる発明は用語集へ拾い上げ、根拠のない書き足しは抑える。
- わかりやすさを優先する。独自の語は否定しないが、読者が意味を取れないまま説明なしに語りださない。用語集への登録は読者に見えないので、登録しただけでは説明したことにならない。
- 登録されていないことだけで、生成モデルの造語と断定しない。作者の意図した新語、既存資料からの登録漏れもある。
- 一般語、普通の動作・情景、通常の比喩は登録しない。一般語でも、作品の中で新しい定義を持つ名前として使うなら登録する。
- 人物名は `character.md` を正とする。人物が使う能力・肩書は用語集で扱う。

## 2. 書式

```markdown
## 用語

| 用語ID | 正式名称 | 種別 | 定義・適用範囲 | 許容表記・略称 | 避ける表記 | 備考 |
|--------|----------|------|----------------|----------------|------------|------|
| term_001 | 火継ぎ | 技術 | 親方の炉の火を、弟子の炉へ移す作業。炭火に限る。火を強くする力は無い | ― | 火魔法、点火術 | |
| term_002 | 炉札 | 物 | 火継ぎを済ませた炉に下げる木の札。下げてよいのは親方だけ | 札（炉札と分かるとき） | 免許、資格証 | |

## 用語（承認待ち）

| 用語ID | 正式名称 | 種別 | 定義・適用範囲 | 許容表記・略称 | 避ける表記 | 備考 |
|--------|----------|------|----------------|----------------|------------|------|
| term_p001 | 火見 | 行為 | 火継ぎのあと、炉の色が落ち着くまで見張ること | ― | ― | 第2章で初出 |
```

| 列 | 書くこと |
|----|----------|
| 用語ID | 正式な表は `term_NNN`、承認待ちは `term_pNNN`。承認待ちを正式な表へ移すときは新しい `term_NNN` を振り、備考に元の ID を残す |
| 正式名称 | 本文で使う名前。必須 |
| 種別 | `場所` / `組織` / `制度` / `技術` / `現象` / `物` / `行為` / `役職` / `その他` のどれか。本文の使い方と型がずれていないかを照合する手がかりになる |
| 定義・適用範囲 | 何を指すかと、どこまで当てはまるか（できないこと・当てはまらない対象）。必須。名前だけ登録して空にしない |
| 許容表記・略称 | 同じ概念を指す別の書き方。「、」区切り。無いときは `―`。似ているだけの別概念を入れない。正式名称と同じ種別の物事を指す書き方だけにする（役職の名前の略称に、行為を指す語を入れない） |
| 避ける表記 | 同じ概念を指すが使わない書き方（汎用の言い換え、別作品の語など）。「、」区切り |
| 備考 | 初出の章、作品をまたいで共通に使う語は `継承: <参照先>` など |

- 見出しは、正式な表が `## 用語`、承認待ちが `## 用語（承認待ち）` と完全に一致するものだけを用語集として扱う。番号付き（`## 7. 用語`）でもよい。
- 列は見出しの名前で読む。列の順は入れ替えてもよい。
- 同じ許容表記が複数の用語を指すなら、備考に使い分けを書く。自動置換の対象にしない。
- 地名・組織名が `world.md` の本文にもあるなら、説明を食い違わせない。

### 旧形式

`## 用語集`、`## 技術・用語`、`## 特殊用語` などの見出しで、箇条書き（`- **語**: 定義`）や2列の表（`| 用語 | 意味 |`）で書いた用語集は、名前と定義だけを読む旧形式として扱う。許容表記・避ける表記の照合はしない。新しい書式へ移すのは作者が求めたときだけにする。

## 3. 書く側の規則（起草・清書・あらすじ）

1. 作品固有の名前は、正式な表の正式名称または許容表記で書く。避ける表記は使わない。
2. 新しい名前、または名前のない新しい仕組み・規則・由来が必要になったら、**本文に出す前に** `## 用語（承認待ち）` へ登録案を書く。備考に初めて使う章を書く。正式な表へは自分で移さない。
3. 登録案の無い造語と、設定に無い仕組み・規則・由来の説明は書かない。普通の日本語で書ける物事は普通の日本語で書く。
4. 清書では新しい名前や設定を足さない。避ける表記を正式名称へ戻すのと、規則5の言い換えを添えるのは清書の範囲に入る。
5. **初出の説明**: 独自の語を本文・あらすじ・ログライン・キャラクター紹介で初めて出すときは、その文か同じ場面のすぐ近くで、読者が意味を取れるようにする。
   - 普通の言葉の言い換えを添えるか（「親方の炉の火を弟子の炉へ移す火継ぎ」）、動作や物で見せる。説明は用語集の定義の範囲にとどめ、事実を足さない。
   - 説明を次の章まで後回しにしない。一度だけ出して説明しないまま終える語は、出さないか普通の言葉にする。
   - ログラインでは独自の語を一つまでにし、ほかは普通の言葉で書く。あらすじの冒頭で独自の語を続けて並べない。
   - 人物が知らない語、謎として伏せる語は、謎であることが読者に分かるように書く（「誰も意味を知らない『火見』という言葉」）。この形なら、意味を明かすのは後の章でよい。
   - **定義文を写さない**。用語集の定義は読者への説明文ではない。定義の文を地の文や台詞へそのまま、またはほぼそのまま貼り付けない（「平民でも持つのが基本の身分証を持たない」）。
   - **説明は視点人物が知りうる形で示す**。視点人物がその場で見る・聞く・推し量る・人から聞くことのできる範囲で意味を取らせる（衛兵が服を指して「蛮族」と叫ぶ。連れが「たぶん身分証のことだ」と言う）。視点人物がまだ知りえない意味（言葉が通じない、来たばかりで制度を知らない）は、地の文で言い切らず、聞き取った音・推測・謎として出す。
6. **一字の語を略して使わない**: 一字の漢語（口・白・端・打・間・赤 など）と、動詞から作った名詞（届き・払い・送り など）を、一般の意味とずれる作中の特定の物事を指す名詞として使わない。読者には何のことか取れないので、独自の語として扱い、普通の語に置き換える（言い換えを添えるだけで済ませない）。
   - 判定の物差しは「その語をふつうの辞書の意味で読んで、指す物事が取れるか」。取れなければ置き換える。
   - **述語と合わせて読む**。語だけを辞書で引くと、一般の意味を持つ字（端・口・間）はいつも「取れる」になる。「端は、次だ」の「端」はへりではなく、へりの霧を払う仕事を指す。「端が弱い」は、へりで余韻が弱いことを指す。述語（次だ・弱い・消す・聞こえない）がへりという場所に合わなければ、略用とみなす。
   - **動詞から作った名詞も洗い出す**。「速さは、届きではない」の「届き」は、余韻が遠くへ届くことを名詞に縮めている。一字の漢字だけを洗い出すと、送り仮名の付いたこの形を落とす。
   - **置き換えで意味を変えない**。縮めた語は、元の意味をそのまま開いて置き換える。原因・条件・程度・対象を、文脈から推した別の語に替えない。「打が弱いと端が白い」を「二打の間隔が短いと端が白い」にすると、白い原因が「打つ力」から「間隔」に替わり、設定の因果が変わる。正しくは「打つ力が弱いと」。元の意味が一つに定まらないときは置き換えず、候補を挙げて作者に確かめる。
   - 置き換えたら、前後の文で「何が・何によって・どうなるか」が変わっていないかを読み比べる。設定資料（`world.md` の地の文や用語の定義）を置き換えたときは、設計書の章出来事と食い違っていないかも確かめる。
   - 置き換えの例: 「打が弱い」→「鐘を打つ力が弱い」、「口まで届く」→「港口まで届く」、「白が残る」→「白い霧の帯が残る」、「継ぎが浅い」→「火継ぎが浅い」、「端は、次だ」→「港口の端は、次の夜明けだ」、「速さは、届きではない」→「速く打っても、遠くへ届くわけではない」。
   - 一般の意味のまま使う一字の語（「手」「音」「口を開く」「白い」）と、一般の意味が指す物事と一致する略称（「炉札」を指す「札」）は対象外。

7. **定義の手順・条件どおりに描く**: 用語集の定義に手順や条件がある語（種別が技術・制度・現象のもの）は、本文・設計でもその手順・条件どおりに描く。
   - 定義が「空に見える線を指で追う」なら、本文でも空の線を見て追う。「星の位置を測って砂へ移す」と別の手順で描かない。
   - 定義に条件（「〜するまで確定しない」）があれば、台詞や地の文でその条件と食い違うことを言わせない（「確定する前でも札を出せます」）。人物の言い違い・誤解として書くなら、そうと分かるようにする。
   - 描き方を変えたくなったら、本文より先に、用語集の定義を直す案を `## 用語（承認待ち）` の備考か完了報告で出す。本文だけを変えない。

### 既存の用語の描写と新しい設定の線引き

| 区分 | 例 | 扱い |
|------|----|------|
| 描写（登録しなくてよい） | 火継ぎの場面で、親方が火箸で炭をつまみ、弟子の炉へ移す手つきを細かく書く | 既存の用語が指す物事を、動作・感覚・道具で細かくしただけ |
| 新しい設定（宣言が要る） | 「火継ぎは満月の夜にしかできない」「一度移した火は戻せる」 | 登録語に無い能力・制約・手順・可否（〜できる／〜してはならない）を足している |

### 生成モデルによる差（推奨）

- 独特な造語を多く作るモデル（造語、名前のない規則、定義のずれが出やすい）では、規則2の宣言、規則5の初出の説明、規則6の一字の語を省かない。用語集に先に登録しても、本文やログラインで説明なしに並べやすい。仕事の動作や現象を一字の漢語に縮めやすい（「打」「白」「届き」）。自分で照合すると、一般の意味を持つ字（端）と動詞から作った名詞（届き）の略用を見落としやすいので、書いたモデルとは別のモデルで照合する。書き終えたら、承認待ちへ足した語と理由を報告に書く。
- 発明を自然な語で書くモデル（一般語を組み合わせた語で、造語と気づきにくい）では、仕組みや決まりを書いたら用語集に載せる。読者向けの説明は足りていても、登録が漏れやすい。
- 発明が少ないモデル（一般語や型どおりの語に流れやすい）では、企画の段階で作品固有の用語を数語作り、設計書でそれを使う場面を用意する。

## 4. 承認待ちを正式な表へ移すか

| 観点 | 移さない例 |
|------|------------|
| 普通の日本語で書けるか | 「炉の前の石床」で足りる場所に名前を付ける |
| 一般語と衝突しないか | 一般語（例: 番台）と同じ字面で、炉の見張り台という別の意味を持たせる |
| 定義の型と本文の使い方が一致するか | 行為として定義した「火見」を、本文では「火見を棚に置いた」と物として使う |
| 既存の用語・設定と矛盾しないか | 「炭火に限る」火継ぎを、油の灯で行う |
| 繰り返し使い、場面に効くか | 一度しか出ない説明のための名前 |
| 一字の語ではないか | 「打」「白」のような一字の語を正式名称にする。一字の許容表記は、一般の意味が指す物事と一致するとき（「炉札」の「札」）だけ認める |

## 5. 用語照合の判定

| 区分 | 問題例 | 正常例 | 振り分け |
|------|--------|--------|----------|
| 避ける表記 | 「火魔法で炉に火を移した」 | 台詞で、よそ者が「火魔法か」と誤解する | 正式名称へ戻す。人物の誤解・俗称なら残す |
| 未登録の名前 | 「炉守の位を継いだ」（どこにも定義が無い） | 「鞴」「鉄床」などの一般語 | 抑える、または拾い上げて登録案 |
| 名前のない仕組み・規則・由来 | 「この村では、火継ぎは三日に一度しかできない」 | 手つきを細かく描くだけの描写（§3 の線引き） | 抑える、または名前と定義を付けて拾い上げる |
| 癖の規則への格上げ | `character.md` で親方の癖の「槌を三度鳴らす」を、本文で「槌を三度鳴らさなければ打ってはならない」と村の決まりにする | 本文でも親方一人の癖として書く | 規則にするなら拾い上げ、癖のままなら本文を戻す |
| 登録語の意味の逸脱 | 「炉札を下げると炉に火が点いた」（札に力を持たせた） | 札の有無で売ってよいかが決まる | 抑える。定義を広げたいなら作者に確認 |
| 定義の型と使い方のずれ | 行為の「火見」を「火見を棚に置いた」 | 「火見のあいだ、炉の前を離れない」 | 定義を直すか本文を直すかを作者に確認 |
| 承認待ちに登録案がある新語 | ― | 宣言どおり、登録案の定義の範囲で使っている | §4 の観点で移すか判断する |
| 初出の説明不足 | 第1章の冒頭で「火継ぎを終えるまで、炉札は下げられない。」とだけ書き、二つの語の説明が第3章まで無い。ログラインに独自の語を三つ並べる | 「親方の炉の火を弟子の炉へ移す火継ぎを終えるまで、売ってよい印の木札――炉札は下げられない。」。前後の文脈から意味が取れる語 | 抑える。語は消さず、用語集の定義の範囲の言い換えを初出に添える。登録の有無とは別に判定する |
| 一字の語の略用 | 「継ぎが浅いと、赤は朝までに戻る。」（継ぎ＝火継ぎ、赤＝炉の赤い火）。「炉の端は、次だ。」（端＝炉の端の火を整える仕事）。「速さは、移りではない。」（移り＝火が弟子の炉へ移ること） | 「火継ぎが浅いと、炉の赤い火は朝までに元の色へ戻る。」。「手で鐘の縁をたどる」「炉の端に灰を寄せる」のように、述語と合わせて読んでも一般の意味のままの一字の語 | 抑える。普通の語に置き換える（§3 の規則6）。語だけでなく述語と合わせて読み、動詞から作った名詞も洗い出す。修正案は元の意味をそのまま開き、原因・条件を別の語に替えない（「継ぎが浅い」→「火継ぎが浅い」であって「火の色が薄い」ではない）。機械では拾えないので文脈で判定する |
| 定義の手順・条件と描き方のずれ | 用語集「火継ぎ＝親方の炉の火を、火箸で弟子の炉へ移す」なのに、本文で「弟子が炭を吹いて自分で火を起こすことを火継ぎと言う」。用語集「炉札は火継ぎのあと親方だけが下げる」なのに、台詞で「火継ぎの前でも札は下げられる」 | 定義どおりの手順を、動作を細かくして描く（§3 の線引き）。人物の誤解として書き、誤解だと分かる | 作者に確認。定義を直すか本文・設計を直すかを決める（§3 の規則7）。種別が技術・制度・現象の語は、定義の手順・条件を一つずつ本文・設計と照らし合わせる |

- 設計書と企画書を本文より先に照合する。ずれが設計の段階で生まれていれば、本文だけを直しても残るため。
- 機械の照合（構造・表記）が0件でも、未定義概念が無いとは言えない。名前のない規則・格上げ・型のずれは文脈を読んで拾う。
- 検査だけを頼まれたときは、本文も `world.md` も直さない。拾い上げも登録案として報告に書くだけにし、自動で登録も削除もしない。

## 6. 報告の雛形

保存先は `novels/<作品>/_reader/terminology_YYYYMMDD_HHMM.md`。

```markdown
# 用語照合

- 種別: 用語照合
- 起動: ユーザー明示
- 日時: YYYY-MM-DD HH:MM
- 対象: world.md, character.md, design_specification.md, proposal.md, _novel_text/novel_text01.md …
- 未確認の範囲: なし（または、読めなかったファイル・範囲）
- 用語集の形式: 新しい形式 / 旧形式（読取互換） / 未整備
- ハッシュ: （`novel_glossary.py --json` の hashes を写す）
- 書いた役 / 検査した役: Grok（goal） / Claude（別セッション）。同じなら「自己検査」と書く
- 件数: 区分別（避ける表記 N、未登録の名前 N …）、振り分け別（抑える N、拾い上げる N、保留 N）

## 機械の照合

（`novel_glossary.py` の構造・表記の結果。0件でも未定義概念なしの保証ではない）

## 設計書・企画書

| No. | 区分 | ファイル:行 | 原文の引用 | 照合先の用語ID | 理由 | 振り分け | 修正案・登録案 |
|-----|------|-------------|------------|----------------|------|----------|----------------|

## 本文

| No. | 区分 | ファイル:行 | 原文の引用 | 照合先の用語ID | 理由 | 振り分け | 修正案・登録案 |
|-----|------|-------------|------------|----------------|------|----------|----------------|

## 拾い上げの登録案

（§2 の表にそのまま貼れる行）

## 正常例（件数に入れない）

| ファイル:行 | 語・文 | 残した理由 |
```
