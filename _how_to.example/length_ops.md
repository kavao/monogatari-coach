# 文章の伸縮操作規定（LENGTH-OPS）

清書、および規定量調整（目標字数に合わせて本文を伸縮する作業）で、使ってよい操作と使ってはならない操作を定める。出来事を足して増やす技法は [子エピソードによる増量](episode/general/episode_sub_episode.md) に分け、加筆工程でだけ使う。

**発動条件**: 清書、規定量調整、規定量調整から加筆・改稿工程へのエスカレーション、章の目標字数があるときの執筆前・企画の設計密度の判定（§4.7）のとき読む。それ以外では読まない。清書の作法そのものは [rewrite.md](rewrite.md) を正とし、本書は「長さを変える操作」の境界だけを扱う。

---

## 0. 規範語

| 語 | 意味 |
|---|---|
| **しなければならない**（MUST） | 絶対要件 |
| **してはならない**（MUST NOT） | 絶対禁止 |
| **すべきである**（SHOULD） | 強い推奨。外す場合は理由を記録する |
| **してもよい**（MAY） | 任意 |

---

## 1. 基本原則

文章を長くする・短くする操作は、字数の操作ではなく、**情報をどの方向に変換するか** の操作である。

### 原則1 判定の基本

> **字数が変わったとき、読者の頭の中で何が増え、何が減ったか。**

字数だけが増えて読者の受け取るものが増えない操作は冗長化（OP-P）であり、禁止する。

### 原則2 工程境界

- 清書と規定量調整は、**物語世界で起きたこと（CANON FACT）を変えない** 工程である。追加・変更・削除のいずれもしない。
- 本文に書かれている表現（SURFACE FACT）の増減は、清書と規定量調整でも行ってよい。
- CANON を追加・変更する操作（OP-E・OP-W）は **加筆工程** にだけ属する。
- CANON を削除する操作（OP-S）は **改稿工程** にだけ属する。

| 工程 | CANON | 使える操作 | ユーザー承認 |
|---|---|---|---|
| 清書 | 不変 | OP-P 除去・OP-T・必要最小限の OP-R | 不要（通常の清書依頼） |
| 規定量調整 | 不変 | OP-P 除去・OP-T・OP-R・OP-C | 候補ごとの事実確認（§6.2） |
| 加筆工程 | 追加・変更 | OP-E・OP-W | 必要 |
| 改稿工程 | 削除 | OP-S | 必要 |

### 原則3 最小編集

- 目標範囲に入れるために **必要な最小限の変更だけ** を行う。
- 許容帯（§4.2）に入った時点で、それ以上の伸縮操作をしてはならない。

## 2. 用語

| 用語 | 定義 |
|---|---|
| **CANON FACT** | 物語世界で起きたこと。出来事・行動・所持品・関係・情報の授受・心境の変化・過去・因果。本文から省略しても物語からは消えない |
| **SURFACE FACT** | 現在の本文に明示的に書かれていること。OP-R で増え、OP-C で減る |
| **既出事実リスト** | 調整対象の区間に関係する CANON の一覧。OP-R が使ってよい「既出」の範囲を決める唯一の基準（§2.1） |
| **状態変化** | 出来事の前後で、情報・関係・所持品・立場・感情・目的・認識のいずれかが変わること |
| **持ち帰り（carry_back）** | 子エピソードが本筋に渡すもの。後の場面で参照・使用される |
| **局所的効果（local_payoff）** | 後の場面では使われないが、その場面自体が読者に与えるもの（人物への愛着・情緒・笑い・世界の手触り・緊張後の休息など） |
| **解像度** | 一つの出来事をどれだけ細かい単位（動作・感覚・心理・反応）で書くか |
| **上位の意味** | 複数の出来事を束ねたときに残る意味（例：「再会したが関係は戻らなかった」） |
| **情報量** | 読者がその文から新たに受け取るもの（事実・感覚・心理・関係の手がかり）の量。既に受け取ったものの言い換えは 0 と数える。ただし、意図された感情の強度・リズム・語り口の変化は情報として数える |
| **床** | 作品・場面に設定された最低字数（場面の下限、Beat の下限）。許容帯とは別に満たす |
| **許容帯** | 規定量調整の目標範囲。目標字数と上下の許容比で定める（§4.2） |

### 2.1 既出事実リストの作り方

- 基準は **調整前の本文** である。本文に書かれた事実はすべて既出とする。
- 時系列イベント（CHRONOS）を登録している作品では、当該場面のイベントを照合して合わせる。
  - 本文にあり、イベントに無い事実: 既出に含める。イベントの登録漏れとして報告する（調整は止めない）
  - イベントにあり、本文に無い事実: 既出に含める（本文から省略された CANON）。報告する
  - イベントと本文が **矛盾する** 事実: 規定量調整を始めない。どちらを正とするかを推測せず、著者へ返す
- 意味の照合は機械では確定できない。イベントがある場面では、調整を始める前に **作業者がイベント一覧と本文を照合し、矛盾が無いことを確かめる**。著者には、矛盾の疑いがあるときだけ相談する。照合の根拠は記録し、作業の終わりの報告にも載せる。照合後に本文またはイベントが変わったら、照合をやり直す。
- イベントを登録していない場面では、調整前の本文がそのまま CANON である。

## 3. 操作の分類

| ID | 操作 | 長さ | CANON | SURFACE | 属する工程 |
|---|---|---|---|---|---|
| **OP-P** | 冗長化（Padding） | ↑ | → | →（言い換えのみ） | **禁止** |
| **OP-T** | 引き締め（Tighten） | ↓ | → | → | 清書・規定量調整 |
| **OP-R** | 解像度展開（Resolve） | ↑ | → | ↑ | 清書（最小限）・規定量調整 |
| **OP-C** | 収束（Condense） | ↓ | → | ↓（上位の意味で保存） | 規定量調整 |
| **OP-S** | 脱落（Strip） | ↓ | **↓** | ↓ | **改稿工程のみ** |
| **OP-E** | 出来事展開（Expand） | ↑ | **↑** | ↑ | **加筆工程のみ** |
| **OP-W** | ひねり（tWist） | ± | **変更** | 変更 | **加筆工程のみ** |

```text
OP-P  冗長化     = 記述量↑ / 情報量→
OP-T  引き締め   = 記述量↓ / 情報量→ / CANON→ / SURFACE→
OP-R  解像度展開 = 記述量↑ / 情報量↑ / CANON→ / SURFACE↑
OP-C  収束       = 記述量↓ / 個別情報↓ / CANON→ / SURFACE↓ / 上位の意味→
OP-S  脱落       = 記述量↓ / CANON↓（意味損失圧縮）
OP-E  出来事展開 = 記述量↑ / 状態変化↑ / CANON↑
```

- OP-P は意味を増やさずに字数だけ増やす。OP-T は意味を減らさずに無駄な字数だけ減らす。
- OP-C は意味を保存する圧縮、OP-S は意味を失う圧縮である。

### 3.1 冗長化（OP-P）

物語上の機能を持たない反復・迂回・形容。

| 型 | 例 |
|---|---|
| 同義反復 | 「彼は悲しかった。胸が締めつけられるような、深い悲しみだった」 |
| 抽象への逃げ | 「とても美しく、言葉にできないほどの光景」 |
| メタ前置き | 「言うまでもないが」「ここで少し説明しておくと」 |
| 迂言 | 「〜することができた」「〜という状況になった」 |
| 結論の反復 | 段落末で、直前の内容をまとめ直す |
| 事実の再確認 | 「太郎は花子に会ったことに気づいた」（会った、を既に書いている） |
| 枕詞・修飾句の連打 | 同じ特徴的な語句（「十三時間机に縫い付けられた」「キーボード焼けした指」）を場面の中で何度も置く |
| 葛藤のやり直し | 接触や台詞のたびに、同じ迷いを最初から考え直す（気持ちが前へ進まない） |
| 数値による計測 | 「向かい合った距離は数十センチもない」（実感ではなく定規の数字） |
| 定型の情景の締め | 段落や Beat の終わりごとに、同じ型の情景（季節の空気・設備の音）を置く |

増量（OP-R）は「出来事を足さず、元文を消さずに増やす」という制約のため、すでに使った安全な語句を繰り返して字数を稼ぐ方へ流れやすい。場面全体で同じ語句が3回目になる書き足しは採用せず（意図したモチーフは除く）、増量のあとは続けて清書して、残った繰り返しを要所の1〜2回に絞る。

**例外**: 修辞的反復・意図的反復は OP-P に含めない。

```text
来ない。
まだ来ない。
あいつは、来ない。
```

事実としては同義反復だが、焦燥・リズム・語り口を増やしているので、情報量は 0 ではない。

OP-P の判定は、候補の抽出（§6.1）と人またはモデルの確認の二段で行う。抽出だけで違反と確定してはならない。

### 3.2 引き締め（OP-T）

CANON・SURFACE・上位の意味を変えずに、表現だけを短くする。

| 型 | 例 |
|---|---|
| 迂言の圧縮 | 「彼は走るという行動を開始した」→「彼は走り出した」 |
| 冗長な修飾の削除 | 「非常にとても大きな」→「大きな」 |
| 重複語の統合 | 「まず最初に」→「まず」 |
| OP-P の除去 | §3.1 の典型の削除 |

**注意**: 文を短くした結果、出来事の一部が消えたら OP-T ではない（例：「鍵を渡して別れた」→「別れた」は鍵の授受を消しているので OP-S）。

### 3.3 解像度展開（OP-R）

既出事実リストの範囲内で、SURFACE を増やす。

| 軸 | 何を書き足すか | 例 |
|---|---|---|
| 行動分解 | 一つの動作を構成動作に割る | 「食べた」→取る・見る・匂う・口に運ぶ |
| 感覚 | 視覚・音・匂い・触覚 | 改札の電子音、ホームの風 |
| 心理 | 期待・迷い・判断 | 声をかけかけて、足が止まる |
| 相手の反応 | 他者がどう返したか | 少し驚いた顔をする |
| 個性 | その人物固有の仕草・解釈 | 以前と変わらない癖で髪を耳にかける |
| 過去との接続 | **既出の** 過去と結ぶ | 三年前なら迷わず声をかけていた |
| 原因・結果 | **既出の** 事実の範囲で因果を明示 | なぜ足が止まったか |

- 既出事実リストにない過去・因果・出来事・選択を書いた場合、それは OP-R ではなく OP-E である。
- モデルは「既出」の範囲を緩く解釈しやすい。OP-R を指示するときは、既出事実リスト（少なくとも調整前の本文と、登録があればイベント一覧）を **指示に明示して渡さなければならない**。判定は自己申告ではなく、事後の事実確認（§6.2）で行う。
- OP-R は **必要量だけ** 適用する。すべての軸を埋めると過描写になる。

### 3.4 出来事展開（OP-E）

CANON を増やす。**加筆工程でだけ使う**。手順と契約は [子エピソードによる増量](episode/general/episode_sub_episode.md)。

| 軸 | 内容 |
|---|---|
| 障害 | 思い通りに進まない要素を一つ挟む |
| 選択 | 人物が何かを捨てて何かを選ぶ瞬間 |
| 余波 | 出来事のあと、人物や関係がどう変わったかの一場面 |
| 伏線 | 後で意味を持つ情報・小道具 |
| 子エピソード | 本筋とは別の小さな出来事の挿入（§5 の契約必須） |

### 3.5 収束（OP-C）と脱落（OP-S）の違い

```text
元：改札を抜けて花子を見つける → 声をかけかけてやめる → 花子も気づく → 二人とも無言

OP-C（意味保存）：三年ぶりに会った二人は、何も言えなかった。
  CANON   → 変化なし（発見・躊躇・無言は物語世界では起きたまま）
  SURFACE → 減少（個々の動作は本文から消えた）
  上位の意味「再会したが関係は戻らなかった」が残っている

OP-S（意味損失）：太郎は駅で花子に会った。
  躊躇と無言という、物語上の意味が消えている
  後の場面で「あのとき声をかけなかった」を参照すると矛盾に見える
```

## 4. 工程別規則

### 4.0 工程の流れ

```text
規定量調整
  │
  ├─ 開始前 ─→ 既出事実リストを作る（§2.1）。イベントがある場面は著者の照合を待つ
  │
  ├─ 減量 ─→ OP-P除去 → OP-T → OP-C ─→ 許容帯に入る → 完了
  │                                   └→ 入らない → 停止して報告
  │                                                  ↓
  │                                       改稿工程（ユーザー承認後に OP-S）
  │
  └─ 増量 ─→ OP-T（OP-P の除去分を把握）→ OP-R ─→ 許容帯に入る → 完了
                                              └→ 入らない → 停止して報告
                                                             ↓
                                                  加筆工程（ユーザー承認後に OP-E、§5 契約付き）
```

### 4.1 清書

長さは読み味・テンポ・情景密度を優先し、増減を許容する（[rewrite.md](rewrite.md)）。規定量調整のあとに続けて行う清書では、ユーザーの字数を仕上がり目標とし、床を割らないところで削るのをやめる。仕上がり目標との数%（5%以内）の差は誤差として扱い、合わせ直さない（増量には戻らない）。そのため規定量調整は、清書で削る分の余地（既定 +8%）を足した字数を目標にする。初稿から ±10% を超えて変わったときは、その理由を完了報告に一行書く。±10% は目安であり、完了の条件にしない。CANON は変えない。

**しなければならない**
- OP-P の候補を確認し、機能を持たないと判断したものを除去する。
- 清書の前後で CANON が一致する（事実の追加・変更・欠落が無い）。

**すべきである**
- 迂言を圧縮する（OP-T）。
- 一文一義に整え、読点の過多を整理する。
- 抽象的な形容は、本文に既にある具体へ寄せる。
- 段落の長さと改行のリズムを大きく変えない（場面のテンポは段落構成に乗っているため）。

**してはならない**
- OP-E・OP-W を用いる（新しい出来事・事実・転換点・予想外の情報を足す、筋をひねる）。
- 出来事の削除・順序変更をする（OP-S）。
- 修辞的反復・意図的反復を OP-P として削る。

### 4.2 規定量調整（共通）

**許容帯**

```yaml
length_target:
  target_chars: 4000
  tolerance:
    lower: 0.97
    upper: 1.03
  scope: beat        # beat | scene | chapter
  max_passes: 3      # 増量・引き締めを合わせた調整の最大試行回数
```

**床との関係**

- 許容帯の上限（`target_chars × upper`）が床を下回る設定は、両立しないので受け付けない。
- 実効の下限は `target_chars × lower` と床の大きい方とする。床で引き上げた場合はその旨を報告する。
- 許容帯の中でも、床に届いていなければ完了としない。

**しなければならない**
- 許容帯に入った時点で、それ以上の伸縮操作をしない。
- 一回の調整は一方向（増量か減量のどちらか）で行う。増量で許容帯の上限を超えた場合、減量に転じてよいのは OP-T だけとする。
- `max_passes` に達しても許容帯に入らない場合、調整を停止し、不足または超過の字数と原因の区間を報告する。却下された候補も試行回数に数える。
- 増量の候補は、機械の検査（元文が残っているか、言い換えの反復が無いか）を通れば採用し、候補ごとに著者へ尋ねない。引き締め・収束の候補は、採用する前に事実の欠落が無いことを著者が確かめる（§6.2）。
- 終わったら、主要な変化（字数の前後、足した文と消えた文、章末と次の場面のつながり）を著者に一度だけ報告し、「これでよいか」を尋ねる。開始前と保存前の2回は尋ねない。気になる箇所は、この報告を見たあとで著者が指摘する。

**してはならない**
- OP-E・OP-W・OP-S を用いる。
- 増量と減量を往復して字数を合わせる（振動の防止）。

### 4.3 規定量調整：増量

**しなければならない**
- OP-P を用いない。
- まず OP-R を適用する。
- OP-R の適用後、事実確認（§6.2）を行う。CANON の追加が見つかった候補は採用しない。
- OP-R だけで許容帯に届かない場合、規定量調整を停止し、**加筆工程へのエスカレーション** を求める。
- 開始時の不足率（§4.7）が 10% 以上なら OP-R を始めず、設計追加（子エピソード）を提案して停止する。不足率の目標は余地を含めた増量の目標とする。欠落 Beat があるときは、先に欠落を埋める。

**すべきである**
- OP-R の適用は一箇所に集中させず、場面の山場（Beat の転換点）に配分する。
- 「後半ほど分量が減る」問題には、Beat 単位で許容帯を持ち、不足した Beat から部分的に展開する。
- エスカレーション時は、不足字数と、OP-E を挿入する候補位置（Beat ID）を併せて報告する。不足率に応じた手段の目安は [子エピソードによる増量](episode/general/episode_sub_episode.md)「不足量に応じた手段の選択」。

**優先順**

```text
1. OP-R 解像度展開（行動分解・感覚・心理・相手反応・個性）
2. OP-R 解像度展開（既出の過去・既出の因果）
3. 届かない → 規定量調整を停止 → 加筆工程へエスカレーション
×  OP-P・OP-E は規定量調整の全段階で禁止
```

### 4.4 規定量調整：減量

**しなければならない**
- 後の場面から参照されている CANON を本文から消す場合、OP-C で上位の意味として残す。
- 伏線（`carry_back` が設定された要素）を本文から消さない。
- OP-P 除去・OP-T・OP-C で許容帯に届かない場合、停止して超過字数と区間を報告する。

**優先順**

```text
1. OP-P の除去（ほぼ無損失）
2. OP-T 引き締め
3. OP-C 収束：local_payoff のみの子エピソード → carry_back が軽い子エピソードの順に、場面から要約へ畳む
4. 届かない → 規定量調整を停止 → 改稿工程へのエスカレーション（OP-S はそちらで扱う）
```

### 4.5 加筆工程

OP-E・OP-W はこの工程にだけ属する。

- 規定量調整からのエスカレーションで加筆工程に入る場合、ユーザーの承認を得る。
- OP-E で追加した出来事は §5 の契約を満たし、イベント登録している作品では時系列イベントに登録する。
- 加筆工程のあとに規定量調整へ戻る場合は、追加した出来事を既出事実リストに加えてから行う。
- 執筆前に設計へ子エピソードを足すとき（§4.7）も、ユーザー承認後の OP-E として同じ契約に従う。

### 4.6 改稿工程

OP-S はこの工程にだけ属する。

- ユーザーの承認を得てから行う。
- 削る前に参照チェック（§6.3）を行い、参照があれば OP-S をせず OP-C に戻す。
- CANON からの削除として記録する。イベント登録している作品では、該当イベントの削除または未配置への退避を、イベント側の承認手順で行う。伏線欄（`_meta.md`）も確認する。

### 4.7 執筆・企画（設計密度）

書いてから Deepen で伸ばすより先に、出来事の数で分量を用意する。Deepen（OP-R）は少量の不足だけに使う。

**章の目標字数の取り先**: ユーザーが明示した字数か、`design_specification.md` の章の「**分量目安**」の書き出しの字数だけ。どちらも無ければ密度の判定を保留する。`_meta.md` の実測字数や場面の床（`chars_floor`）を章の目標に読み替えない。

**設計密度**（本文が無い段階。`uv run python tools/design_density.py novels/<作品> [--chapter N] [--target N]`）: 章の目標字数 ÷ 章の番号付き出来事の件数。数えるのは行頭（字下げなし）の番号付き項目だけで、入れ子の補足やコード例は数えない。

| 1項あたりの見込み | 判定 | 対応 |
| --- | --- | --- |
| 500〜800字 | 推奨帯 | そのまま書く。会話中心は短め、描写中心は長めでよい |
| 1000字超（または親の目的・障害・結果・変化が薄い） | 少なすぎ | 設計へ子エピソードを足す（ユーザー承認後） |
| 300字未満（または同じ山場の言い換え） | 多すぎ | 統合案を出して止まる（反映は改稿工程と同じ承認） |
| それ以外 | 帯の外だが許容 | 件数だけで直さない |

件数の出発点は目標 ÷ 800 〜 目標 ÷ 500（8000字なら10〜16項、4000字なら5〜8項）。「常に12項」のような固定数は使わない。

**不足率**（本文がある段階）: `max(0, T − C) ÷ T`。`C` は同じ範囲の本文字数。

- 規定量調整の `T` は余地を含めた増量の目標（§4.1）。10% 以上なら OP-R を始めず、設計追加を提案する。
- 自動修復の `T` は対象場面の床。当面は計測して報告するだけで、修復は止めない。
- 計測した不足率は場面ごとの記録（`_metron/<scene_id>/shortage_log.jsonl`）に残す。

**設計追加の手順**（承認後）:
1. `design_specification.md` の章へ項目を足す（「誰が何をした」の一文）。
2. 同じ子エピソードを `_metron/<scene_id>/episodes.yaml` に、状態変化・接続・持ち帰り・局所的効果を含めて登録する。本文が無いうちは `span_pending: true` とし、本文を書いたあとに `span` の開始・終了の引用を補って `span_pending` を外す。範囲が決まるまで収束・脱落の対象にならない。
3. イベント登録している作品では、当該場面の events を既存の承認手順で足す。METRON を使う作品では Beat と `chars_hint` を配り直す。
4. そのあと本文を書く。

## 5. 子エピソード契約

子エピソードを **追加するとき**（OP-E）も、**畳む・削るとき**（OP-C / OP-S）も、同じ契約で判定する。演算子・配置・禁止パターンは [子エピソードによる増量](episode/general/episode_sub_episode.md)。

```yaml
child_episode:
  id: "CE-xxx"
  parent: "親シーン / Beat ID"
  operator: INTERRUPT | PREPARE | DISCOVER | RELATE | HESITATE | CONSEQUENCE | MIRROR | BREATHE
  insert_at: "親のどの位置に挿すか"
  depth: 1                 # 1 または 2（入れ子は 2 階層まで）
  state_change:            # 最低 1 件必須
    - kind: info | relation | item | position | emotion | goal | belief
      who: "誰の状態か"
      before: "..."
      after: "..."
  connections: []          # 原因 / 障害 / 情報 / 関係 / 感情 / 後続条件 / 結果拡張
  carry_back:              # 本筋に何を持ち帰るか（後の場面で使われるもの）
    - what: "..."
      used_at: "後のどのシーン / Beat で使われるか"
  local_payoff:            # その場面自体が読者に与えるもの
    - kind: character | emotion | theme | humor | atmosphere | rest
      what: "読者に何を体感させるか（具体的に）"
  est_chars: 0
  order_note: ""           # 推奨順序から外す場合のみ理由を書く
  chronos: true            # 時系列イベントとして登録するか
  checks:                  # deletion / change / connection / duplication / dominance / strength
    deletion: pass
```

`state_change.kind` の例：

```yaml
- kind: belief
  who: "主人公"
  before: "魔法学校は楽しい場所だと思っている"
  after: "危険な場所でもあると知る"

- kind: emotion
  who: "主人公"
  before: "怖がっている"
  after: "覚悟を決める"
```

### 5.1 追加時の規則（加筆工程）

- `state_change` が空の子エピソードは追加してはならない。
- `carry_back` と `local_payoff` が **両方とも空** の子エピソードは、冗長化とみなし追加してはならない。
- `local_payoff` は具体的に書く。「雰囲気を出す」「世界観を伝える」のような抽象的な記述は空とみなす。
- イベント登録している作品では、追加した子エピソードを登録する。

### 5.2 減量時の規則

| 条件 | 扱い |
|---|---|
| `carry_back` 空・`local_payoff` 空 | 最優先の畳み対象（OP-C）。脱落（OP-S）は改稿工程で検討 |
| `carry_back` 空・`local_payoff` あり | 次の畳み対象（OP-C）。要約文に `local_payoff` の要点を残すべきである |
| `carry_back` あり・参照先が存在 | 脱落禁止。畳む（OP-C）のは可。`carry_back` の要素と `state_change.after` を要約文に残す |
| `carry_back` あり・参照先が既に削除済み | 契約を更新したうえで再判定 |

### 5.3 子エピソードの入れ子と収束

追加する子エピソードの入れ子は 2 階層までとする。収束（OP-C）の判定では、場面を任意の深さまで割って同じ契約で考えてよい。

```text
親：主人公は初めて魔法学校へ行く
├─ CE：家を出る
├─ CE：途中で迷う
│   ├─ 道を間違える
│   ├─ 地図を見る
│   ├─ 知らない少女に聞く
│   └─ 少女も新入生だったと判明   ← state_change: relation（友人候補）
├─ CE：校門を見る
├─ CE：上級生に絡まれる             ← state_change: belief（学校は危険でもある）
└─ CE：教室へ入る

収束（OP-C）：「登校途中で最初の友人ができた」
```

## 6. 検査

検査は、モデルの出力を信用せず事後に確認するためのものである。

### 6.1 冗長化の候補抽出

以下はすべて **候補の抽出** であり、違反の確定ではない。§3.1 の例外（修辞的反復・意図的反復）に当たらないかを確認してから除去する。

| 検査 ID | 対象 | 方法 |
|---|---|---|
| CHK-P1 | 迂言・定型の水増し句 | パターン照合（「〜することができた」「〜という状況」「言うまでもなく」等） |
| CHK-P2 | 近接した同義反復 | 近い位置の文同士の類似度判定 |
| CHK-P3 | 段落末の結論反復 | 段落の冒頭と末尾の意味の重なりを判定 |
| CHK-P4 | 削除テスト | 「この文を消すと読者は何を失うか」に答え、「なし」なら候補 |
| CHK-P5 | 抽象形容の連打 | 形容語の密度が閾値を超える文を抽出 |

### 6.2 事実確認（CANON 不変チェック）

清書・規定量調整で最も重要な安全装置。本文の差分ではなく、物語の差分を見る。

```text
入力：既出事実リスト、調整前の本文、調整後の本文

a. 調整後の本文にあり、既出事実にない事実          → CANON 追加（OP-E）。採用しない
b. 既出事実と矛盾する調整後の本文                  → CANON 変更（OP-W）。採用しない
c. 調整前の本文にあり、調整後の本文から消えた事実  → OP-C の要約文で覆われているか §6.4 で確認
                                                     覆われていない → 欠落（OP-S）。採用しない
```

- 欠落（c）の対象は、今回の調整で本文から消えた事実だけである。既出事実リストにあっても調整前の本文に書かれていなかった事実（本文から省略済みのイベントなど）は、調整後の本文に無くても欠落としない。
- 清書では a・b・c（欠落）のいずれも 0 件でなければならない。確認は作業者が旧版と清書稿を比べて行い、著者の承認は要らない。
- 規定量調整でも a・b・c（欠落）のいずれも 0 件でなければならない。欠落を伴う減量は改稿工程で扱う。
- 規定量調整では、意味の照合を機械で確定できない。そのため、出来事を落としうる引き締め・収束の候補は、**採用前に著者が確認する**。確認に出すもの: 差分、消えた・短くなった文の一覧、消えた人名・固有名詞・所持品。
- 増量の候補は機械の検査で採用し、候補ごとの確認は求めない。そのかわり、作業の終わりに一度だけ、元文に対応しない新しい文の一覧と、調整前の本文や人物資料に無い人名・固有名詞を含めた報告を著者に見せる。新しい出来事の混入はここで指摘を受けて直す。
- 時系列イベントとの開始前の照合は作業者が行い、矛盾の疑いがあるときだけ著者に相談する。

### 6.3 参照チェック

OP-S を行う前に、その CANON が後の場面・時系列イベント・伏線から参照されていないかを確認しなければならない。参照があれば OP-S は不可とし、OP-C に戻す。

### 6.4 収束品質チェック

OP-C の要約文が上位の意味を本当に保存しているかを、契約の側から検査する。

| 検査 ID | 対象 | 方法 |
|---|---|---|
| CHK-C1 | 状態変化の保存 | 畳んだ部分の `state_change.after` が、要約文から読み取れるか |
| CHK-C2 | 持ち帰りの保存 | `carry_back.what` が要約文に残っているか（後の参照先で唐突にならないか） |
| CHK-C3 | 感情の向き | 元の場面の感情の向き（肯定／否定／保留）が要約文で反転していないか |

CHK-C1・C2 のいずれかに失敗した要約文は、OP-S とみなす。

### 6.5 停止判定

| 検査 ID | 条件 | 処理 |
|---|---|---|
| CHK-L1 | 許容帯に入り、床にも届いた | 伸縮操作を終了する |
| CHK-L2 | 増量中に許容帯の上限を超えた | OP-T のみで戻す |
| CHK-L3 | `max_passes` に達した | 停止し、不足・超過の字数と区間を報告する |
| CHK-L4 | 増量で OP-R が尽きた | 停止し、加筆工程へエスカレーションする（不足字数と OP-E の候補位置を添える） |

## 7. 指示テンプレート

「もっと長く」「もっと短く」とだけ指示すると、モデルはほぼ確実に OP-P（言い換え・形容・まとめの反復）か OP-S（出来事の削除）に流れる。**量ではなく、増やす・減らす単位を指定する**。「使い切れ」「すべて入れろ」のような指示は過描写を招くので避ける。

### 7.1 清書

```text
以下の本文を清書してください。
- 出来事・人物・所持品・情報の授受・心境の変化は一切変えないこと
- 同義反復、段落末のまとめ直し、メタ前置き、迂言を削ること
- ただし、焦りや強調のために意図的に繰り返している箇所は残すこと
- 一文一義に整え、読点を整理すること
- 段落の長さと改行のリズムは大きく変えないこと
- 新しい出来事・過去・設定・転換点を足さないこと
```

### 7.2 規定量調整：増量

```text
以下の本文を {target_chars} 字（許容 {lower_chars}〜{upper_chars} 字）に増量してください。
- 使ってよい過去・因果は、次の既出事実リストの範囲に限ること：
  {既出事実リスト}
- 新しい出来事・人物・過去・選択は追加しないこと
- 増やすのは、既にある出来事の解像度のみ：
  動作の分解／感覚描写／人物の迷い・判断／相手の反応／その人物らしい癖
- 必要な字数を満たす分だけ増やし、すべての項目を埋めようとしないこと
- 増量は Beat の転換点に重点的に配分すること
- 同じ内容の言い換えや、段落末のまとめ直しで字数を稼がないこと
- 許容範囲に届かない場合は、無理に増やさず、届かなかった字数を報告すること
```

### 7.3 規定量調整：引き締め

```text
以下の本文を {upper_chars} 字以下に引き締めてください。下限は {lower_chars} 字です。
- 同義反復・まとめ直し・前置き・迂言と、冗長な修飾だけを削ること（意図的な繰り返しは残す）
- 出来事・人物・所持品・情報の授受・心境の変化は一つも消さないこと
- 文の順序と段落の区切りを変えないこと
- 新しい文を足さないこと
- 範囲に入った時点で削るのをやめること
```

### 7.4 規定量調整：減量（収束まで）

```text
以下の本文を {target_chars} 字（許容 {lower_chars}〜{upper_chars} 字）に減量してください。次の順で削ること。
1. 同義反復・まとめ直し・前置き・迂言（意図的な繰り返しは残す）
2. 修飾の整理
3. それでも足りなければ、以下の子エピソードを一文の要約に畳む：{対象 CE 一覧}
- 次の要素は必ず残すこと：{carry_back 一覧}
- 畳んだ一文には、その子エピソードで変わったこと（{state_change.after 一覧}）が読み取れるようにすること
- 出来事そのものを物語からなかったことにしないこと
- 許容範囲に入った時点で削るのをやめること。届かない場合は超過字数を報告すること
```

### 7.5 加筆工程：子エピソード挿入（OP-E）

規定量調整からエスカレーションし、ユーザーが承認した場合にだけ使う。

```text
Beat {ID} の {位置} に、子エピソードを一つ挿入してください。
- その子エピソードで、{情報 / 関係 / 所持品 / 立場 / 感情 / 目的 / 認識} のいずれかを変化させること
- 次のどちらか（または両方）を満たすこと：
  - 得たものを Beat {後続ID} で使えるようにする
  - その場面自体で、読者に {人物への愛着 / 情緒 / 笑い / 世界の手触り / 休息} を具体的に体感させる
- 出力の末尾に、追加した出来事と状態変化を箇条書きで列挙すること（時系列イベント登録用）
```
