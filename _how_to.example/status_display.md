# 章末ステータスと本文内の通知（型の葉）

> 既定では読まない。作品の config.md が `CHAPTER_STATUS | TEXT` のとき、作品の `status_display.md` の「本文内の通知」を「使う」にするとき、Gate A / Gate B で型や通知の演出を選ぶときにだけ読む。
> 規則（値の意味・印・字数・保存）の正本は `.rulesync/rules/workflow-specification.md`「章末ステータスの表示（CHAPTER_STATUS）」。この葉は「どう見せるか」の基準とテンプレートだけを持つ。

## 1. 使い方

1. 型を一つ選ぶ（§2）。異世界・迷宮・ゲームの作品では、ジャンルに合う型を2〜3個示して作者に選んでもらう。
2. `uv run python tools/novel_status_display.py init novels/<作品> --style <ID>` で、作品フォルダに `status_display.md` を作る。§3 の型のテンプレートと §5 の骨組みが写される。本文内の通知の例を写すときは `--notice <例の ID>`（§4）。
3. 写した `status_display.md` を作品向けに書き換える（見せる項目、尺度、告知の口調、記号）。写したあとは、この葉を改訂しても作品側は書き換えない。
4. config.md の基本情報表に `| CHAPTER_STATUS | TEXT |` と `| CHAPTER_STATUS_STYLE | <ID> |` を書く（本文内の通知だけ使い、章末は出さない作品は `SYNOPSIS` のまま）。

## 2. 型の一覧

| ID | 型 | 中身 | 向く作品 |
|---|---|---|---|
| `notice_log`（基準） | 通知ログ型 | 獲得・進化・称号を、声やシステムの告知として一行ずつ並べる | 転生もの・成長が速い主人公。天の声やシステムの声が世界の仕掛けになっている作品（『転生したらスライムだった件』などが型の基準） |
| `status_window` | ステータス窓型 | 名前・種族・レベル・能力値・スキルを一覧の窓で示す | 数値の伸びそのものを楽しませる作品。迷宮攻略・ゲーム世界 |
| `diff` | 差分型 | 章で動いた値だけを「旧 → 新」で示す | 項目が多く、毎章全部を出すと重くなる作品 |
| `experience_log` | 経験ログ型 | 人物ごとに、何を経験して何が変わったかを数値なしの箇条書きで示す | 数値を出さずに変化を記録したい作品。関係や身体の変化が主の作品 |
| `card` | 鑑定書・ギルドカード型 | 作中の書類や鑑定の結果として書式どおりに示す | 冒険者ギルド・鑑定の制度がある作品。数値の出どころを作中の道具にしたい作品 |

- 基準の作品名は型の説明のために挙げるだけ。台詞・記号・スキル名・告知の決まり文句は写さない（作品の再現にしない）。例の文言はすべてこの葉で独自に作ったもの。
- どの型でも、章番号・作者の目線の言葉（「この章で」「読者の皆さん」）は書かない。
- 値は作品の `status_display.md` の台帳と一致させる。

### 2.1 陳腐になりやすい点と外し方

| よくある処理 | 起きる問題 | 外し方の例 |
|---|---|---|
| 毎章、全項目を並べる | 読み飛ばされる。緊張が消える | `diff` にする。転機の章だけ全体を出す |
| 数値が上がるだけ | 成長が記号になる | 本文の実感（息が続く、刃が通る）と数値をずらして書き、ずれ自体を話の種にする |
| 告知が説明係になる | 世界の仕掛けが便利な解説役になる | 告知は事実だけを告げ、意味は人物に考えさせる。誤りや沈黙を混ぜる |
| ブロックで本文の山場を言い直す | 余韻が消える | 本文で書いたことの要約を書かない。値と名前だけにする |

## 3. 型のテンプレート

テンプレートは章末ブロック（`<!-- status:begin -->` と `<!-- status:end -->` の間）に入れる中身の枠。`〈 〉` の中を作品の値に置き換える。`novel_status_display.py init` は、選んだ型のコードブロックを作品の「書式」節に写す。

### テンプレート: notice_log

```text
《記録》〈主体の名〉より通知
・〈獲得したもの〉を得た
・〈変化した能力〉が〈新しい段階〉に至った
・称号〈称号の名〉が付与された
```

記入例:

```text
《記録》灯台の声より通知
・技能「潮読み」を得た
・夜目が第二段階に至った
・称号「嵐を越えた者」が付与された
```

### テンプレート: status_window

```text
┏ 〈名前〉 ┓
種族：〈種族〉　段階：〈レベルや階位〉
体力 〈値〉／〈上限〉　魔力 〈値〉／〈上限〉
技能：〈技能1〉、〈技能2〉
称号：〈称号〉
┗━━━━━━┛
```

記入例:

```text
┏ ミナト ┓
種族：人　段階：七
体力 82／120　魔力 15／40
技能：短剣術、罠外し
称号：迷宮の新顔
┗━━━━━━┛
```

### テンプレート: diff

```text
〈名前〉
・〈項目〉 〈旧値〉 → 〈新値〉
・〈項目〉 〈旧値〉 → 〈新値〉
```

記入例:

```text
ミナト
・段階 六 → 七
・罠外し 初級 → 中級
```

### テンプレート: experience_log

```text
**〈見出し〉**
- 〈人物〉：〈経験したこと〉。〈変わったこと〉。
- 〈人物〉：〈経験したこと〉。〈変わったこと〉。
```

記入例:

```text
**この夜に変わったこと**
- ミナト：初めて一人で罠を外した。手の震えが収まるのが早くなった。
- サラ：ミナトを先に行かせた。背中を預ける怖さが少し薄れた。
```

### テンプレート: card

```text
【〈書類の名〉】
氏名：〈名前〉
等級：〈等級〉（前回 〈前の等級〉）
特記：〈特記事項〉
発行：〈発行した組織〉
```

記入例:

```text
【探索者登録証・更新票】
氏名：ミナト
等級：銅二（前回 銅一）
特記：第三層の単独踏破を確認
発行：港町探索者組合
```

## 4. 本文内の通知の演出の例

本文の途中の通知は世界の仕掛けそのものなので、共通の決まりは置かない。作品の `status_display.md` の「本文内の通知」節で、作者と次の項目を決める（決めていない項目があれば、その作品では本文内の通知を書かない）。下の例は出発点で、作品はこれに縛られない。`init --notice <ID>` で写せる。

### 演出の例: heaven_voice

| 項目 | 内容 |
|---|---|
| 使うか | 使う |
| 主体 | 世界そのものの声（姿はない） |
| 出方 | 頭の中に直接響く |
| 届く範囲 | 本人だけ |
| きっかけ | 獲得・進化のとき |
| やりとり | 告げるだけ。問いには答えない |
| 置き方 | 独立した行 |
| 書式 | 二重山括弧で囲み、事務的な口調で一文 |
| 括弧 | 《》 |
| 頻度の方針 | 転機だけ。戦闘の最中は鳴らさない |

### 演出の例: god_announce

| 項目 | 内容 |
|---|---|
| 使うか | 使う |
| 主体 | 主人公を転生させた神 |
| 出方 | 声で告げる。ときどき冗談を混ぜる |
| 届く範囲 | 本人だけ（周りには聞こえない） |
| きっかけ | 獲得のときと、神の気まぐれ |
| やりとり | 人物の問いに答える。口調と意思を持つ |
| 置き方 | 台詞として地の文に織り込む |
| 書式 | 隅付き括弧で囲む |
| 括弧 | 【】 |
| 頻度の方針 | 章に数回まで。説明役にしない |

### 演出の例: system_stream

| 項目 | 内容 |
|---|---|
| 使うか | 使う |
| 主体 | ゲームのシステム |
| 出方 | 視界の端に文字が流れる |
| 届く範囲 | その場の参加者全員 |
| きっかけ | 戦闘の結果、取得、等級の変化 |
| やりとり | 告げるだけ |
| 置き方 | 独立した行と、地の文への織り込みを使い分ける |
| 書式 | 角括弧で囲み、短い名詞止め |
| 括弧 | ［］ |
| 頻度の方針 | 戦闘中は流し続けてよい。日常の場面では出さない |

### 演出の例: appraisal

| 項目 | 内容 |
|---|---|
| 使うか | 使う |
| 主体 | 鑑定の道具（または鑑定の技能） |
| 出方 | 鑑定したときに結果の文が浮かぶ |
| 届く範囲 | 鑑定した人だけ |
| きっかけ | 人物が鑑定したとき |
| やりとり | 問いの形で呼び出すと答える |
| 置き方 | 独立した行 |
| 書式 | 山括弧で囲み、項目と値を並べる |
| 括弧 | 〈〉 |
| 頻度の方針 | 鑑定の場面だけ |

- 主体や仕掛けに名前を付けるときは、本文に出す前に `world.md` の `## 用語（承認待ち）` に登録案を書く。人物と話せる主体（`god_announce` など）は `character.md` にも置く。
- 「括弧」は機械が読む行。書いた括弧の中は、lint の「本文に数値のステータス」の候補から外れる。括弧を使わない作品は空欄にする（候補に出たものを作者が残してよい）。

## 5. 作品の status_display.md の骨組み

`init` が作る骨組み。節の名前は機械が読むので変えない。

```text
# ステータス表示 — 〈作品名〉

型: 〈ID〉（〈写した日〉に `_how_to.example/status_display.md` から写した。以後は作品側で直す）

## 書式

（型のテンプレート。本文の章末ブロックはこの書式で書く）

## 項目の定義

| 項目 | 尺度 | 初期値 | 見せる転機 |
|---|---|---|---|

## 本文内の通知

| 項目 | 内容 |
|---|---|
| 使うか | 使わない |
| 主体 | |
| 出方 | |
| 届く範囲 | |
| きっかけ | |
| やりとり | |
| 置き方 | |
| 書式 | |
| 括弧 | |
| 頻度の方針 | |

## 台帳

各章が終わった時点の値。チャットモードの作品は、その章のセッションの `[STATE UPDATE]` を章の終わりまでたどって決める。たどれない値は「未確認」。

| 章 | 項目 | 値 | 根拠 |
|---|---|---|---|
```
