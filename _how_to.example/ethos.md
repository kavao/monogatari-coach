# 物語の倫理観（ETHOS）

> 原資料: `C:/Users/Owner/Downloads/物語での倫理観/ETHOS.md` v0.3
> 
> この葉は、原資料を Monogatari Coach の創作技法用に整理した標準雛形である。簡易版を入口とし、必要な作品だけ詳細版へ進む。

## 0. 使い方

倫理観は、人物を善人・悪人に分類するための採点表ではない。誰が何を正しいとし、誰を配慮の範囲に含め、どの損失なら引き受けるかを設計するために使う。

既定では読まない。次のいずれかに当たる作品で選定する。

- 倫理的な決断や、規範の違いを物語の推進力にする。
- 忠義と恩義、共同体と個人、法と救済などを衝突させる。
- ユーザーが ETHOS の適用を明示する。

作品へ採用した場合も、既存の Gate B の selected を自動変更しない。作業用 `_how_to/` 索引がある場合は、標準葉を作業用索引へ追随させるまで選定対象外として扱う。

### 0.1 最小の記入（三角形）

まず、視点人物について次の三つを一文ずつ書く。

| 要素 | 問い |
| --- | --- |
| 義務 | 何をしなかった自分を許せないか |
| 禁止線 | 何だけは絶対にできないか |
| 代償 | それを選ぶと社会・関係・生活から何を失うか |

例:

> 義務: 自分を救った人を見捨てない。<br>
> 禁止線: 無実の人に罪を着せない。<br>
> 代償: 命令に逆らえば職と仲間からの信用を失う。

この三つが同時に掛かる場面を、主要な転換点に置く。場面の記録は `design_specification.md` に「何を選び、何を失い、何が残ったか」を散文で残す。数値の `scene_stakes` YAML は保存しない。

## 1. 世界・人物・語り手を分ける

同じ規範について、次の三層を混ぜない。

| 層 | 問い | 作品資料 |
| --- | --- | --- |
| 世界の公式倫理 | 社会や集団は何を正しいとするか。違反をどう制裁するか | `world.md` |
| 人物の内心倫理 | 本人は何を優先し、何を拒み、誰まで配慮するか | `character.md` |
| 語り手・作者の立場 | 語り手はどの距離から描くか。作者はなぜこの規範を描くか | 語り手は `world.md`、作者の採用理由は `_meta.md` |

作中社会の規範を設定しただけで、作品がそれを肯定したことにはならない。前近代や架空社会を描く場合も、現代の読者に近い価値観を持つ人物を置けるが、意図的な異物なのか、作品上の許容なのかを決めておく。

## 2. 簡易版（通常はこちら）

簡易版は人物の重要度にかかわらず使える。詳細版の深度表を簡易版へ適用しない。簡易版の主要人物に `os_base` や `moral_circle` を要求しない。

### 2.1 世界・集団

次の問いに短く答える。

- 何を根拠に「正しい」とするか。
- 誰を道徳的に配慮するか。誰を勘定の外に置くか。
- 何をすると「人として終わった」とみなされるか。
- 違反したとき、誰がどのような損失を与えるか。
- 建前と現場の慣行はどこでずれるか。

例:

> 港町の商人組合では、血筋より約束と信用を重く見る。手形を故意に踏み倒す者は、法に裁かれなくても仲間から締め出される。一方、組合外の労働者は保護の対象に入りにくい。

### 2.2 人物

既存の人物プロフィールへ任意ラベルとして記入する。新しい人物見出しを作ったり、`character_checklist.yaml` の必須項目へ追加したりしない。

- 優先価値: 何を守ると自分らしくいられるか。
- 配慮の範囲: 誰までを道徳の勘定に入れるか。
- 禁止線: 社会が許しても本人が拒む行為は何か。
- 義務: しなかった場合に自分を許せないことは何か。
- 服従の理由: 信じて従うのか、損得・恐怖で従うのか、従わないのか。

恩の対象・授受・返済状況の台帳は倫理ラベルに含めず、既存の人物関係記録で管理する。恩義の価値が人物の選択に影響するときだけ、優先価値や義務から参照する。

恩・義理・返報の授受と関係の設計は [恩義設計論（ON）](episode/general/episode_obligation.md) が担当する。そこで作品に記録した恩の台帳は、技法ファイルではなく、作品側の人物関係記録へ置く。

## 3. 詳細版（必要な作品だけ）

詳細版では、時代・文化・階層を人物の判断を考えるためのプリセットとして使う。分類そのものを文明の発展度や倫理的優劣と解釈しない。時代層は、氏族層・古代層・中世層・近世層・近代層・現代層のように、社会編成と支配的規範の違いを示す便宜的な名前である。文化圏と階層も同じく、人物の差を作るための補助線であり、優劣の順位ではない。

### 3.1 倫理基盤（OS）

人物が判断するときの優先価値を、必要なものだけ複数選ぶ。数値は顕著性の補助であり、合計を 1.0 に正規化しない。決断を自動計算しない。

| ID | 倫理基盤 | 判断の問い |
| --- | --- | --- |
| `OS-KIN` | 血縁 | 身内か、血に報いたか |
| `OS-HON` | 名誉 | 侮辱されたか、面目を失わないか |
| `OS-LOY` | 忠誠 | 主・組織・国家を裏切らないか |
| `OS-ON` | 恩義 | 受けた具体的な恩を返したか |
| `OS-SAC` | 聖法 | 神・戒律に反しないか |
| `OS-COM` | 共同体 | 閉じた集団の和と存続を守るか |
| `OS-CON` | 契約・信用 | 約束と信用を守るか |
| `OS-CIV` | 公共 | 見知らぬ成員を含む公共に責任を負うか |
| `OS-RIG` | 権利 | 個人の自由と平等を侵さないか |
| `OS-CAR` | ケア | 目の前の弱い者を守るか |
| `OS-SRV` | 生存 | 今を生き延びるか、生き延びさせるか |

`OS-HON` は世間の評価、`OS-LOY` は誓約の対象、`OS-ON` は受けた給付への返済である。同じ「主君を守る」でも、面目・忠誠・恩義のどれが理由かを分けて書く。

### 3.2 配慮の範囲

誰を道徳の勘定に入れるかを記す。単純な同心円とは限らないので、除外対象も書く。

`kin`（家族） / `in-group`（家・村・部族） / `co-religionists`（同じ信仰） / `subjects`（同じ支配下） / `humans`（人類） / `sentient`（感覚ある存在）

### 3.3 深度

深度表は詳細版を選んだ人物だけに適用する。

| 深度 | 対象 | 必須の目安 |
| --- | --- | --- |
| `minor` | 端役 | 所属、上位1つの OS、服従の理由 |
| `supporting` | 準主要 | OS 3項目、禁止線 0〜1、集団の最悪の恥 |
| `major` | 主要 | 優先価値、配慮の範囲、禁止線、義務、服従の理由、残余 |

### 3.4 公式倫理・内心倫理・制裁

世界の建前、人物の信念、違反への制裁を分ける。人物が従う理由は、信念・損得・恐怖・反抗のいずれかとして記す。規範違反を描いた場面では、制裁が発動したのか、選択的に見逃されたのか、隠蔽されたのか、保護されたのかを示す。

## 4. 倫理的決断の書き方

1. 視点人物の優先価値、禁止線、義務を確認する。
2. 対立相手にも、その人物なりの優先価値を与える。
3. 禁止線に触れる選択肢、制裁を受ける選択肢、誰かを見捨てる選択肢を並べる。
4. 選んだ行動と、外部から受ける制裁を記す。
5. 選ばなかった価値が残す負い目や関係の変化を、次の場面へ引き継ぐ。

衝突は「どちらかが愚かだから」ではなく、善悪を計算する基準が異なる結果として描く。前近代の人物を冷酷さだけで特徴づけず、ケアや慈悲が誰に向くのか、その範囲と他の価値との競合で差を出す。

### 4.1 現代の日常の例

同じ職場の二人が、ミスを隠して担当者を守るか、利用者へ正直に報告するかで対立する。

> 選択: 主人公は、同僚の処分を軽くするために、報告書の表現を穏当なものへ書き換える。完全な隠蔽はしない。<br>
> 失うもの: 利用者への説明が遅れ、主人公は「身内をかばった」と同僚以外からの信用を失う。<br>
> 残るもの: 同僚を見捨てなかったという自己像は守られるが、被害を受けた利用者へ十分に向き合わなかった負い目が残る。次の場面では、主人公が自分から経緯を説明する動機になる。

ここでは `OS-CAR`（目の前の同僚を守る）と `OS-CIV`（利用者を含む公共への責任）が競合している。どちらかを無条件に正解とせず、選択の代償と残余を次の行動へつなぐ。

### 4.2 前近代・架空社会の例

主家への忠誠を重んじる城下町で、主人公は反乱の疑いをかけられた農家の子どもを匿っている。子どもは実際には無実だが、主君は見せしめの処罰を命じる。

> 選択: 主人公は命令に従わず、夜のうちに子どもを寺へ逃がす。主君へは「見失った」と報告する。<br>
> 失うもの: 主君への不服従が露見すれば、家の役目と俸禄を失い、家族にも連座の危険が及ぶ。<br>
> 残るもの: 子どもの命を救った一方、主君との誓約を破った恥と、家族を危険にさらした負い目を抱える。後の場面で、主人公は家族へ真実を話すか、なお隠し続けるかを迫られる。

ここでは `OS-LOY`（主君への忠誠）、`OS-CAR`（目の前の弱者の保護）、`OS-HON`（家名と面目）が衝突している。前近代の社会にもケアや慈悲は存在し、その配慮が主家・家族・村のどこまで届くかで葛藤の形が変わる。

## 5. 導入時の境界

この葉は創作技法の雛形である。次の機能は現行の執筆手順として扱わない。

- CHRONOS への `ethos_shift` 自動登録や、原稿からの無承認抽出。
- ETHOS 専用 validator、数値による倫理判断、本文の自動矯正。
- GEN-1〜6 や IF-O2 に相当する生成時の倫理・恩義情報注入。

これらは [ETHOS 次期計画](../_workingspace/plans/20260926_ethos-tool-integration.md) で、構造検査は P2、変化記録と CHRONOS 接続は P3、生成時注入は P4 として別々に検討する。作品へ採用した場合の記録先は、導入計画の所有表に従う。

## 6. 点検

- 世界の公式倫理と人物の内心倫理を同じものとして書いていないか。
- `veto`（本人が拒む行為）と、社会の `PF-3`（最悪の恥）を混同していないか。
- `cannot_forgive_self_for`（しなかった自分を許せない条件）を、単なる目標と取り違えていないか。
- 制裁の担い手と執行の程度が、行動の結果に対応しているか。
- 簡易版の人物へ詳細版の深度表を強制していないか。
- 場面に選択・喪失・残余があり、数値の `scene_stakes` を保存していないか。
- 恩の台帳を倫理ラベルへ重複記録していないか。
- CHRONOS、validator、生成時注入を実装済みの機能として読ませていないか。
