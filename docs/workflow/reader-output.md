# Reader Output

このガイドでは、下読み・書評・一般読者の興味判定を依頼したときに、Monogatari Coach がどこへ結果を保存し、ユーザーが何を確認すればよいかを説明します。

## このドキュメントを使う場面

小説本文を書いたあと、次のような確認をしたいときに使います。

- 商業的な最低基準を満たしているかを下読みしたい
- 冒頭やタイトルで一般読者が読み続けるかを確認したい
- 書評結果をチャットだけでなく、作品フォルダ内へ残したい

保存先と完了条件の正本は [novel-reader-output](../../.rulesync/skills/novel-reader-output/SKILL.md) です。

## チャットへの指示文

下読みを依頼するときは、これだけで動きます。

```text
第1章を下読みして書評を出してください。
```

一般読者の興味判定を依頼するときは、これだけで動きます。

```text
第1章を一般読者の視点で興味判定してください。
```

対象を明確にしたい場合は、作品フォルダや本文ファイルも添えます。

```text
novels/NNN_作品名/_novel_text/novel_text01.md を下読みして書評を出してください。
```

## Monogatari Coach が行うこと

下読みでは、Monogatari Coach は `_how_to/reader.md` を参照し、キャラクター、プロット、文章力、わかりやすさ、独創性などの観点で評価します。

興味判定では、Monogatari Coach は `_how_to/standard_reader.md` を参照し、ペルソナを立てたうえで、タイトル、冒頭3行、最初の1ページの第一印象を判定します。

どちらの場合も、評価本文はチャットではなく `_reader/` に保存します。チャットには判定と要約だけを返します。

## ユーザーが確認できるもの

| 種別 | 保存先 |
|------|--------|
| 下読み・書評 | `novels/<作品>/_reader/YYYYMMDD_HHMM.md` |
| 一般読者の興味判定 | `novels/<作品>/_reader/interest_YYYYMMDD.md` |

チャット側には、次の内容だけが簡潔に返ります。

- 判定
- 重要な理由を1〜3行
- 改善ポイントの要約
- 保存先ファイルパス

## 査証ログとの違い

`_reader/` は評価本文の保存先です。`_workingspace/log/` は作業事実を残す査証ログなので、書評本文そのものは入れません。

たとえば、査証ログには「第1章の下読みを実施し、`novels/<作品>/_reader/YYYYMMDD_HHMM.md` に保存した」という事実だけを追記します。
