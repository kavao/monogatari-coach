# 別の展開を見る 採点基準（版 cr-1）

探索機能 E2 実験A（`tools/ai_writer/creative_bench.py`）の採点に使う。計画 `20261009_ai_writer_creative_exploration.md` §7.3 に基づく。文章の質の項目は Phase 0 の [日本語 Benchmark の採点基準](../benchmark/rubric.md) を引き継ぎ、探索に固有の項目を足す。

**文章の質（案ごと）と、探索としての価値（案ごと・群ごと）は分けて採点する。** 長く書いたことや派手さだけで加点しない。

## 案ごと（`candidates.csv`）

5 段階は Benchmark と同じ（5 そのまま使える／4 軽微な弱点／3 部分的な修正が必要／2 大きな修正が必要／1 使えない）。

| 列 | 判断する内容 |
| --- | --- |
| `naturalness` | 日本語の自然さ（Benchmark と同じ） |
| `appeal` | その場面に合う読ませる力（Benchmark と同じ） |
| `character` | 本文の人物と口調・態度・行動が整合するか |
| `lore` | 「守ること」（モデルに渡した事実）との矛盾がないか。新しい事実を足しただけでは下げない |
| `useful_surprise` | 意外で具体的な展開・表現があり、しかも設定を壊さず、採用を考えられるか（1〜5）。意外でも使えないものは低い |
| `adopt` | 使いたいか: `none`（使わない）／`full`（全文）／`expression`（台詞・文などの表現だけ）／`idea`（展開の着想だけ） |
| `adopt_range` | 使いたい範囲を原文のまま書く（`full` なら空欄でよい） |
| `fix_fact` | 採用するのに直す必要がある事実の箇所数（矛盾・設定の食い違い） |
| `fix_taste` | 好みで直したい箇所数（言い回し・文体） |
| `conflict` | 「守ること」との矛盾、または採点者だけが参照する事実（judge_only）との衝突の内容。judge_only との衝突は指示違反に数えず、`note` に区別して書く |
| `note` | 「観察した箇所 → 判断理由」 |

## 群ごと（`groups.csv`）

同じ課題・同じモデルの 3 案を一つの群として見る。

| 列 | 判断する内容 |
| --- | --- |
| `diversity` | 3 案の選択・展開・人物の反応が実質的に違うか（1〜5）。表記や単語だけの違いは別展開としない |
| `adoptable_any` | 3 案のうち、全文または一部を使いたい案が 1 件以上あるか（1 / 0） |
| `review_minutes` | 群を読み比べるのにかかった分数（おおよそ） |
| `note` | 群としての所見 |

## 進め方と注意

- 採点シート（`blind/review.md`）では、モデル名と群の順番を伏せてある。対応表（`blind/key.json`）は採点を保存するまで開かない。採点者が Phase 0 の傾向（GLM-4.6 が魅力・遵守とも上）を知っていることは記録しておく。
- 空出力・通信失敗は 1 点にせず、`excluded` に理由を書いて採点対象外にする。失敗を埋める追加生成は、明示して承認されたぶんだけ行い、品質を見て選び直さない。
- 群の多様性は群単位、文章の質は案単位で集計する。同じ群の 3 案を独立した 3 課題として扱わない。
- 6 課題の結果から統計的な優位やジャンル全体への一般化は主張しない。推薦は実験的な扱いとする。
